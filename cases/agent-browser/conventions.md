# agent-browser review conventions

Project overlay for the [review-gate](../../skills/review-gate/SKILL.md) skill. Every entry is harvested from maintainer review rounds or recorded cases in this directory; entries carry no authority beyond that provenance. Paths verified against the repository on 2026-07-17.

## Oracles

- **Locator semantics → Playwright.** Any change to `getByRole`/`find role` behavior is checked against the full Playwright `getByRole` contract, not the cases a bug report cites: AX-role to ARIA-name normalization (`image` → `img`), ordered fallback role lists (`role="button none"` must not match `none`), `presentation`/`none` handling, accessible-name matching and its case rules under `--exact`, and first-match versus strict-mode behavior (a deliberate divergence is documented, not silent). **This contract is enumerable, so run it as the forced checklist [getrole-contract.md](../../skills/review-gate/references/getrole-contract.md), not as prose.** Blind-replication A/B (2026-07-20) proved the format matters: the same facts as prose here caught 0/2 findings, as a line-item checklist caught 2/2. Provenance: #1552 round-2 misses; each one already solved by the reference implementation the fix cited.
- **Implicit roles → ARIA in HTML.** The mapping from HTML elements to implicit ARIA roles follows the W3C ARIA-in-HTML spec.

## Error conventions

- Every error path surfaces the AI-friendly guidance, including wrapped and re-wrapped errors. A wrapper that drops the guidance is a regression. Provenance: #1553 round 2.
- Error-message classifiers are checked against every engine's producer set (Chrome CDP, WebDriver, Lightpanda), not only the default engine's. A string that reads as protocol noise in one engine can be the genuine locator-miss path in another, and a committed test that encodes the wrong assumption locks the regression in instead of guarding against it. Provenance: #1553 round 2, the WebDriver "No element ID in response" miss path.
- Validate inputs before expensive setup. An invalid action rejected only after browser launch and locator resolution reports "element not found", an error that names the wrong fault. Provenance: #1553 round 2.
- **Narrowing an error classifier is a contract change with an out-of-diff blast radius.** When a diff makes a classifier predicate (`is_locator_miss`, retryable-error detection, etc.) accept fewer inputs, run `gate.sh producers <shape-regex>`: every error-string producer matching the old broad shape, on a line the diff never touched, is re-checked against the new predicate. A producer whose message no longer classifies surfaces raw. The classifier has two regression surfaces (see the [checklist](../../skills/review-gate/references/getrole-contract.md) classifier matrix): a real miss that no longer classifies (false negative → raw error) AND a benign input whose text trips the classifier (false positive → wrong error). Provenance: #1553 round 3 (F4), `handle_multiselect`'s `Select element not found`.

## House norms

- Comments use prose punctuation: `,`, `;`, or a period, never ` -- ` and never an em dash. Checked by `gate.sh style`.
- External community PRs are not merged directly: recreate the approach on a fresh branch from `origin/main` with `Co-authored-by` credit to the original author, and cover strictly more than the original.
- **Absorption is authorship.** A branch that recreates community PRs is new code: the original authors' green tests verify their happy paths and never count as a lens pass; the full gate runs before the push. Any cross-machine handoff prompt that ends in a push or PR names the gate as an explicit step. Provenance: #1589 round 1 (four maintainer findings on an absorption branch whose "review" was the deterministic layer plus inherited e2e).
- PRs open ready-for-review, not draft. After review starts, append commits and merge main into the branch rather than rebasing.
- **A defect in code the PR ships is fixed in the PR, whether or not the maintainer flagged it and whether or not it predates the branch.** The scope test is "does this PR introduce or ship the code that carries the defect", not "did the reviewer mention it" or "is the line pre-existing". A path new in the branch (a DOM fallback, an AX-tree matcher, a classifier the diff narrows) ships its bugs on merge; punting them as "issue candidate, not flagged" or "pre-existing on main" is a false exemption. Genuinely separate concerns (a deprecated-behavior redesign, a product decision like strict-mode-vs-first-match) are issue candidates; a wrong result in code this PR adds or exposes is not. Provenance: #1552/#1553 round 3 — conflict-resolution and classifier-flattening were caught by the agnostic reviewer, punted on this test, and flagged by the maintainer anyway; the frame-scoping fix was correctly folded in by the same rule.

- **Stream input priority starts at connection setup**: a split WebSocket reader cannot dispatch input until it is spawned. Status, tabs, or cached-frame writes performed before the spawn remain an output-backpressure dependency and must be forced with a stalled peer. Provenance: #1594.
- **Latest-frame delivery includes the transport buffer**: replacing an application-level queued frame is insufficient once prior frames have been accepted by the WebSocket/TCP sink. Pause a real client, let frames accumulate, then resume and assert it does not burst-drain stale frames. Provenance: #1594.
- **Fix the class, not the instance.** When a finding reveals a bug in an operation (clearing an invariant, mutating state before a fallible step, touching a resource that can be in a bad state), `grep` every call site of that operation and audit each in the same commit. The fix is not done until the class is swept, not just the line the finding named. Provenance: #1589 round 3 — three maintainer findings were each the same class as an already-fixed finding, living in a sibling path the earlier fix never enumerated.

## Trust and TLS norms

- **Two trust stores, not one.** An intercepting proxy breaks the connection in two independent places: Chromium rejecting a page certificate, and the Rust CLI rejecting its own outbound peer before the browser is reached. They are different processes with different root sets, and a fix for one is not a fix for the other. Any report of a certificate failure names which of the two is rejecting before a fix is designed. Provenance: #1669/#1670 (2026-08-08), where a Slack-relayed diagnosis pointed at the browser-side PR for a CLI-side failure.
- **One reader per user-supplied certificate file.** `--ca-cert` is consumed by the Chromium SPKI hasher, the rustls root store, and the reqwest clients. Each reading the file its own way is how their accepted input domains drift: a DER certificate was valid for one and invalid for another, a PEM behind a text preamble was the reverse. Any new consumer goes through `ca_bundle`. Provenance: #1670 solution gate.
- **A diagnostic is emitted by the process the user is attached to.** The daemon builds the root store lazily and its stderr is piped and dropped unread, so a warning raised there reaches nobody. Trust diagnostics are computed in the CLI process. Provenance: #1670, where `SSL_CERT_FILE=/nonexistent` produced a downstream `UnknownIssuer` and no explanation.
- **`--ca-cert` takes a path and therefore cannot reach a platform trust store.** On macOS and Windows a proxy CA installed by MDM lives in the Keychain and the certificate store, neither of which is a file. That is what `--use-system-ca` exists for, and why the two options are not twins. On Linux they overlap, because the system store is a file there. Provenance: #1670, verified by installing a CA into the login Keychain and driving it.
- **Sticky CA state is reviewed as a transition matrix.** Cross prior state (`unset`, `set`) with request (`set`, `omit`, `clear`) and every independently constructed launch envelope, including providers. Omission intentionally retains trust, so a dropped clear field is not neutral. Provenance: [#1669 provider clear transition](1669-provider-clear-ca-transition.md).

## Probe norms

- A liveness heuristic that infers death from non-response is checked against every renderer-blocking state the product itself supports before it ships: JS modal dialogs (`alert`/`confirm`/`prompt`, `beforeunload`), debugger pauses, and attach-time pauses (`waitForDebuggerOnStart: true` since #1546). Each of these blocks `Runtime.evaluate` on a live tab. The enumeration source is the repo's own command surface (`dialog accept/dismiss` exists, so dialog-blocked is an input class). Provenance: #1532 round 2, probe misclassified dialog-blocked live tabs as discarded, reproduced in Chrome by the maintainer.
- A fix that turns a hang into a returnable error re-verifies every caller of the failable function at the daemon dispatch layer, not only the `BrowserManager` layer: handlers in `actions.rs` mutate `DaemonState` (ref map, iframe sessions, active frame) before delegating, and those mutations execute even when the delegate now fails. Provenance: #1532 round 2, failed switch preserved the old tab but wiped its refs and frame context.

## BrowserContext lifecycle norms

- Internal daemon exits dispose every registered non-persisted child BrowserContext before autosave, while preserving the persisted primary BrowserContext. The opposite direction matters too: explicit user `close` disposes both child and primary contexts after saving configured state. A child context belongs to work the replacement daemon cannot resume; the primary context belongs to the durable session binding. Provenance: #1068 Review Gate, which found signal and idle shutdown could orphan a recording context and then autosave from that child instead of the primary context.

## Verification norms

- One machine-wide daemon: isolate every verification run with its own `AGENT_BROWSER_NAMESPACE`, or the daemon answers for whichever build started it. Provenance: [shared-daemon case](shared-daemon-cross-worktree-contamination.md).
- Reproduce against a build of the exact commit a report cites before writing any fix; a report's code reading is a hypothesis until the binary reproduces it. Provenance: [#1552 case](1552-getbyrole-implicit-roles-regression.md).
- A drift test asserts the invariant (dispatch succeeded), not the failure message previously observed, and is forced red once before it counts. Provenance: [#1553 case](1553-error-detail-and-help-drift.md).
- CI resolves rust stable at run time (unpinned) and runs `cargo fmt --manifest-path cli/Cargo.toml -- --check` then `cargo clippy --manifest-path cli/Cargo.toml -- -D warnings`. A stale local toolchain produces false green, and running the checks by hand is forgettable. Before push: `rustup update stable`, then run CI's two exact invocations in write mode where needed (`cargo fmt` writes, not just `--check`). Provenance: #1553 round-2 push (needless_borrow on clippy 1.97 a stale local stable missed) and #1553 CI (fmt-dirty `let selected` block pushed because `cargo fmt` write-mode was skipped).
- Code behind an operating-system `cfg` is compiled on that operating system before push. A host-only test suite cannot validate a branch the host removes before type checking. Prefer extracting mixed `Option` and `Result` resolution into an all-platform helper, then run the repository's exact CI command in a read-only-mounted Linux container with build output outside the host checkout. Provenance: #1669 at `cc2a7d5`, where macOS fmt, clippy, and 1,135 tests passed while Linux `cargo clippy` found four type errors in `try_launch_chrome`.
- A new external executable is verified from a clean supported image after every first-party installer and sandbox bootstrap runs. Preinstalling the executable in a development container proves runtime behavior but hides setup incompleteness. Provenance: [#1669 missing certutil setup](1669-certutil-missing-from-installers.md).

## Subsystem invariants (added 2026-07-27, PR #1589 final gate)

- **Two homes for a session flag**: a session setting lives on `DaemonState` (persisted, survives restarts) and on `BrowserManager` (enforces behaviour, dies with the connection). Only the attach paths run `apply_tab_binding_on_attach*`, the single place that copies state to manager; the launch paths (`BrowserManager::launch`, provider connect) do not. Asserting `state.pin_tab` proves nothing about enforcement. Assert the manager's copy, and drive the local-launch path, which is the default and the one every docs example skips (all examples use `--cdp`).
- **Tab topology varies per launch**: a locally launched Chrome sometimes keeps an extra `about:blank` alongside the navigated tab and sometimes does not, so "the session's sole tab" is not a condition a test gets for free. Any pinned-tab scenario that depends on `page_count() == 0` must close the spare tab explicitly, or it silently tests a different path than intended.
- **CDP rejects an explicit `null` for an optional parameter** (added 2026-07-30, PR #1594 gate). `serde_json`'s `json!({"k": parsed.get("k")})` serializes an absent field as `null`, and Chrome answers `-32602 Failed to deserialize params.k - BINDINGS: string value expected`, failing the *whole* command. Any field forwarded from client JSON into a CDP payload needs `.and_then(...).unwrap_or(...)` or conditional insertion, never a bare `.get()`. Because these call sites use `let _ = client.send_command(...)`, the rejection is invisible: the feature silently does nothing. Provenance: `input_keyboard` dropped every `keyUp` and every non-printable key for as long as the stream server has existed.
- **A client-cooperative delivery mode shares one reader task with input** (added 2026-07-30, PR #1594 gate). Under ack pacing the message that releases the next frame is queued behind every input event on the same connection, because `reader_loop` awaits each CDP dispatch in order. Steady-state throughput measured on an idle connection therefore says nothing about throughput during interaction, which is the only state a remote preview is ever in. Measure the mode under concurrent input on the same socket, and compare against the non-cooperative default as the control.

## Fix-round outcomes (2026-07-30, PR #1594 after ctate round 1)

- **A cancellation test whose observable requires reading cannot detect a leaked writer.** Observing "the connection is gone" means reading the socket, and reading un-parks a writer blocked in `ws_tx.send()`, which then sees the shutdown signal and exits cleanly. So the test passes whether the task was owned or detached. The reader half *is* detectable, because an orphaned reader holds the read half open and the client never sees end of stream. Pick the half you can discriminate, state the half you cannot, and verify that one against the binary.
- **`text: ""` is not a safe default for a CDP string parameter.** Measured: `Input.dispatchKeyEvent` with `text: ""` on a printable key fires keydown and inserts no character. Omission is the only correct handling of an absent optional string; empty-string defaulting trades a silent drop for a silent typing regression.
- **A value duplicated between an envelope and its serialized payload needs a test that reads both.** Offsetting the envelope id from the wire id survived every existing test, because they all read the wire value only. The guard is an ack-pacing round-trip: ack exactly what the wire showed and assert the next frame is released.

## Verification norms (added 2026-07-30, PR #1594 F2 autopsy)

- **A client harness that assigns its message handler after `connect()` resolves can drop the connection's first frame.** The seed frame often shares the first TCP segment with the handshake response, so it is parsed in the same tick that `resolve()` runs, before the caller's `onMessage` exists. Under ack pacing this silently makes the client owe an ack it never sent, the server correctly stops sending, and it reads as an intermittent server-side stall. Queue anything parsed before the handler is attached. This produced a confirmed, six-times-reproduced "defect" that was entirely the harness; it cost more than the four real fixes combined.
- **Order is a confound in any A/B where one arm always runs first.** Every stall was observed on the ack arm, which was first in every script. Re-running with push first on a daemon that had just stalled (push 0/10, then ack 1/10 on its first trial) is what made the finding trustworthy enough to spend tracing on. Alternate the arms, or run the suspected-healthy one first.
- **When a latency grows geometrically, measure both directions before blaming the server.** Send-to-ack delays of 33, 71, 116, 191, 317, 546, 908ms looked like a server backlog. Tracing showed the server's ack handling and its next send in the same millisecond: the growth was head-of-line blocking in the client's own outbound queue, behind its own input flood. `writableLength == 0` on the client does not rule this out, because it does not count bytes already in the kernel send buffer.
- **Never restore a mutation with `git checkout --`.** In a force-red harness over uncommitted work it reverts the fix along with the mutation, and every subsequent case reports a meaningless GREEN. Snapshot the files to a temp path and restore from there.

## Subsystem invariant: stream keyboard is platform-split (added 2026-07-30)

Closing a keyboard-shortcut report needs two fixes on two platforms, and neither one alone closes it. Measured against real Chrome on macOS, with the Linux half taken from the reporter of #1615.

| Remote Chrome | What a shortcut needs | Evidence |
|---|---|---|
| macOS | `commands` on `Input.dispatchKeyEvent` | `Ctrl+A` with the correct virtual key selects 0 characters; with `commands: ["selectAll"]` it selects 11 |
| Linux | the correct virtual key code | Reported by the #1615 author, who tested on Linux. Not measured here |

The property belongs to the Chrome the daemon drives, not to the machine the viewer sits at, because `commands` exists to reach the macOS responder chain. A sandboxed deployment therefore needs the Linux half regardless of what the end user runs.

Two open community PRs split along exactly this line: #1499 covers macOS through `commands`, #1618 covers Linux through virtual-key derivation and adds a clipboard bridge. #1615 stays open while either half is missing, which is why two PRs point at it and none closes it.

Also measured, because the two PRs disagree about it: with `commands` present, a `text` field is harmless. All of `rawKeyDown` and `keyDown`, with `text` absent, `text: "a"`, or `text: ""`, select all 11 characters and type nothing. #1499's premise that CDP drops a `keyDown` without `text` was true when written, because omitting the field client-side sent an explicit `null` that CDP rejected; #1594 fixed that root cause, so the workaround it built is no longer needed.
