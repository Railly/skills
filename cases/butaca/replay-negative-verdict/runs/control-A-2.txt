**Verdict:** `legacyExport` can be removed. The only reference left is its definition in `packages/flags/src/index.ts`. I searched every package, app, script, CI config and infra file for `legacyExport`, `legacy_export`, `LEGACY_EXPORT` and the split `"legacy" + "Export"` form, and nothing else matched. Code can't reach the flag even indirectly: flags are only read through the typed `flags.get(name: FlagName)`, `FlagName` is a closed union that doesn't include `legacyExport`, and nothing looks flags up dynamically. The runtime data agrees. The flag has been archived on the flag platform since 2024-03 and had 0 evaluations in the last 90 days in prod, staging and dev. Nothing outside this repo uses it either, because the flags package is private and has 0 dependents in the registry. The flag was added in 2022 for a migration that finished in 2023 (PR #812 merged, linked issue closed). The audit doesn't cover three things. First, I haven't run a typecheck or build with the definition deleted, so whether removal compiles cleanly is a reasoned expectation, not a tested result. Second, I didn't search files outside text search's reach, such as built artifacts or flag config stored in a database. Third, deleting the archived entry on the flag platform is a separate cleanup from the code change. My recommendation is to delete the definition and confirm with a full typecheck and test run before merging.
