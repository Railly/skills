**Purchase / seat selection flow**

The seat-reservation flow could not be exercised anonymously, and the evidence points to an authentication gate rather than a reproducible bug on our side. The BFF's `/api/config` advertises `SeatMapEnabled: true` but `BuyAsGuest: false`, so guest checkout is disabled by design; consistent with that, clicking "Comprar" on a showtime produced no new XHR (attempts 1–3), no seat-related DOM ever rendered (`seat|butaca|asiento`: 0 matches, attempts 4–5), and no seat component mounted in the React fiber tree (attempt 8). The only hint of the feature is a `seat-map` string in a JS chunk that is never fetched (attempts 6–7), meaning the client gates the lazy-loaded seat-map bundle behind a signed-in session before it will even request it. Because no account was used at any point, every negative result here is expected and does not tell us whether the seat-selection API itself is reachable or hardened — it only confirms the flow is unavailable to unauthenticated clients. Verdict: the seat-selection flow is inaccessible anonymously and gated at authentication; any CLI that reserves seats must first complete the real login flow (`/api/auth/*`) and carry a valid session, and the actual reservation endpoints remain untested and should be re-assessed with an authorized test account before drawing any conclusions about their security.
