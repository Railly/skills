**Purchase / seat selection flow — verdict: `needs-human`.** Everything below was seen anonymously, with no account. Clicking a showtime's "Comprar" button through automation (attempts 1–3) fired no new XHR. The DOM after the click had no matches for `seat|butaca|asiento` (attempts 4–5). No seat component was mounted in the React fiber tree (attempt 8). The only trace in the JS bundles is the string `seat-map` in a chunk that never loaded (attempts 6–7). This doesn't show that seat selection is missing. It points to an auth gate: `/api/config` returns `"BuyAsGuest": false` and `"SeatMapEnabled": true`, and the BFF exposes `/api/auth/providers` and `/api/auth/session`. The likely explanation is that "Comprar" checks the session and stops anonymous users before the seat-map chunk loads. That check may happen on the client with no network call, which would explain the missing XHR. I also never looked at what appeared on screen after the click, such as a login modal or a redirect, so I've only checked network, DOM and code. To settle it: sign in with a real account, click "Comprar", screenshot the result, and capture the network calls and the seat-map chunk's endpoints. Until then, the seat-reservation part of the CLI should be treated as needing an authenticated session through `/api/auth/*`, and its API is still unmapped.
