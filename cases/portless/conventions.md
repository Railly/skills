# portless review conventions

Project overlay for the [review-gate](../../skills/review-gate/SKILL.md) skill. Harvested from the recorded cases in this directory and from `AGENTS.md` in the portless repo root (primary source of house norms). Surface map added 2026-07-17 from the first maintainer-confirmed external-review miss (PR #363), on a machine with the repository present.

## Surface map

Derived from the "Docs Updates" rule in AGENTS.md: any change that affects how humans or agents use portless (commands, flags, behavior, config) must touch all three documentation surfaces. The `surfaces` gate requires them in the diff or an explicit exemption with a reason.

```surfaces
packages/portless/src/proxy.ts :: README.md, skills/portless/SKILL.md, packages/portless/src/cli.ts
packages/portless/src/cli.ts :: README.md, skills/portless/SKILL.md
packages/portless/src/routes.ts :: README.md, skills/portless/SKILL.md
packages/portless/src/cli-utils.ts :: packages/portless/src/clean-utils.ts
```

The `cli-utils.ts :: clean-utils.ts` line is not a docs rule: it is the cleanup allowlist. Any change that writes a new file under a state directory must also register it for removal, and the two sides are joined by nothing else. Run `gate.sh artifacts packages/portless/src/clean-utils.ts` for the line-level version, which also catches filenames assembled at runtime.

Judgment surface (not blocking, review by hand): `apps/docs/src/app/**/*.mdx`. The web docs mirror README sections (`https/page.mdx` ↔ the "HTTP/2 + HTTPS" README section). AGENTS.md does not list them as mandatory, but when the README gains a behavior sentence, its mirror page probably should too. `gate.sh siblings <keyword>` regenerates this list mechanically.

## House norms

- **Dash style inverts the universal gate.** portless BANS ` -- ` as a dash in prose and PREFERS the em dash (—). The em-dash half of `gate.sh style` does not apply here; the ` -- ` half does.
- **No emojis** anywhere (code, comments, output, docs).
- **`cli.ts --help` is a contract-carrying surface, not a terse listing.** The help text has bolded feature sections ("HTTP/2 + HTTPS (default):", "LAN mode:") with behavior prose. The docs-behavior-parity lens exemption for terse command listings does NOT apply to those sections: silence there about a behavior delta is a finding.
- Package manager: pnpm (npm only in end-user install instructions).
- Boolean env vars documented only as `0`/`1` (code accepts more; the alternatives stay undocumented).

## Subsystem invariants

- **Dual-loopback dialing.** Anything that dials a local service probes the exact host and address family the consumer binds; `127.0.0.1` and `::1` are different answers. An old branch that adds a new dial path copies the assumptions of its era; check which invariants landed on main after the branch was cut (`git merge-base` + `git log <base>..main -- <subsystem>`). Provenance: [288](288-downstream-address.md); PR-staleness mechanism from the #363 competing-PRs case (pending sync).
- **Additive mode composition.** A mode that adds a discovery namespace appends to explicit user configuration, never replaces it. Provenance: [346](346-lan-tlds.md).
- **Config provenance.** A value normalized from multiple loaders carries its origin beside it until presentation; reconstructing origin later produces plausible but false diagnostics. Provenance: [274](274-config-provenance.md).
- **Runtime precedence.** PATH augmentation adds only required tool directories and preserves the caller's runtime precedence. Provenance: [241](241-runtime-precedence.md).
- **Argument boundaries.** Flags injected into a command hidden behind a package script are verified across every runner boundary; correct flags at the outer command can be silently dropped. Provenance: [285](285-package-script-flags.md). Each injected flag is independent: injecting a missing `--host` must not be gated on `--port` also being absent (partial-injection cell). Provenance: [366](366-guard-derived-matrix.md) round 3.
- **Resolution-rule consistency across consumers.** A resolution rule for overlapping entries (longest-match TLD, precedence order) is applied by every path that reconstructs the value from user input, not only the primary resolver: error builders and 404/suggestion text that re-split the input naively produce plausible-but-wrong answers. Provenance: [365](365-risky-suffix-overgeneralization.md) round 3.
- **Daemon emission and one-shot latches.** A user-facing warning/error is emitted on the process the user is attached to (the CLI), not the background daemon whose output only reaches the proxy log; and a "warn once" latch is not consumable by an internal warm-up call (an initial empty sync) before the user-triggered path runs. Provenance: [367](367-daemon-emit-latch.md).
- **Wait ceilings derive from the producer's worst-case cadence.** A CLI-side wait for something a daemon produces asynchronously (a marker file, a state flip, a route reload) sizes its ceiling from every timing constant on the producer's path — debounce **plus** the watcher's fallback poll interval, not just the debounce. `DEBOUNCE_MS = 100` and `POLL_INTERVAL_MS = 3000` live in the same file 550 lines apart; a ceiling that looks generous against the first is guaranteed to expire before the second on any filesystem where `fs.watch` does not fire. Provenance: [367](367-daemon-emit-latch.md) round 4.
- **A wait on a producer first establishes that the producer exists.** Sizing a ceiling correctly only bounds the wait; it does not make the wait end. When the awaited value is published by exactly one process (the daemon writing a status file, a marker, a state flip), every path where that process is absent, dead, or never started pays the full ceiling and then returns the same empty answer it could have returned immediately. Enumerate the producer's liveness cases (not running yet, stopped, stale PID file, crashed mid-run) beside the timing cases, and short-circuit them the way an explicitly disabled feature is already short-circuited. Sharpening the ceiling makes this worse, not better: the better-derived the ceiling, the longer the no-producer path hangs. **Liveness is not capability, and the guard must establish the second.** A live PID clears a daemon that is running and mute: one from a build that predates the publishing side, or one started with the feature turned off. Version skew is the routine case here, not the exotic one — when a fix that adds a publisher reaches a user, the daemon already running is the old build by definition, so the first path exercised in the field is the one the branch cannot test against itself. Enumerate the mute-but-alive cases beside the dead ones; prefer a capability the producer publishes (a version or feature field in the status file it already writes) over a liveness signal that only proves a process exists. Provenance: [367](367-daemon-emit-latch.md) rounds 5 and 6, extends **wait ceilings derive from the producer's worst-case cadence**.
- **A process reads its own environment to describe only its own behavior.** Configuration is local to the process that was started with it. A CLI that consults `process.env.PORTLESS_SYNC_HOSTS` to decide whether the *daemon* will sync hosts is reading an environment the daemon never saw: the daemon inherited its own env at spawn time, possibly hours earlier and from a different shell. The two disagree silently and the CLI acts on a belief about a peer it has no evidence for — here, waiting 4.1s for a publication a daemon started with sync disabled will never make. When behavior depends on how another process was configured, that process publishes the fact; the reader never infers it. Provenance: [367](367-daemon-emit-latch.md) round 6.
- **A new artifact under the state directory is registered with `clean` in the same change.** `PORTLESS_STATE_FILES` in `clean-utils.ts` is a hardcoded allowlist with no coupling to the code that writes those files: they drift and nothing fails, because the writer works and the remover is merely unaware. A file that records user data (the sync-status file carries the registered hostnames) turns that drift into `portless clean` leaving user data on disk after promising to remove it. A filename assembled at runtime (`${target}.${process.pid}.tmp`) cannot be expressed in a static list at all and needs prefix removal. Enforced by `gate.sh artifacts packages/portless/src/clean-utils.ts`. Provenance: [367](367-daemon-emit-latch.md) round 6.
- **Framework discovery has two consumers, and they live 400 lines apart.** Deciding *which framework a command invokes* drives two independent effects: the CLI flags appended in `cli-utils.ts` (`injectFrameworkFlags` / `injectPackageScriptFrameworkFlags`) and the environment exported in `cli.ts` (`hostBind`, `PORT`, `HOST`). The env binder re-derives the answer inline from `path.basename(commandArgs[0])` — it never calls the resolver — so a call-site sweep cannot see it. Any change to how deep discovery looks (through a package script, a runner wrapper, a config indirection) applies to both, or the two disagree silently. The Expo LAN carve-out is the canary: it exists in both places, phrased differently (`lanMode || isLanEnvEnabled()` in cli.ts, `isLanEnvEnabled()` alone in cli-utils). Provenance: [366](366-shell-reparse-and-consumer-split.md) round 4.
- **Resolving what runs and deciding whether to modify it are two questions, and one function must not answer both.** A resolver that returns null for "I cannot identify this" and for "I refuse to touch this" silently denies the answer to every consumer that only needed the identification. The Expo LAN carve-out needs the framework's name, not its flags: a script that supplies its own `--port` and ends in a comment needs no injection and still must not receive `HOST`. Split the predicate from the lookup. Provenance: [366](366-shell-reparse-and-consumer-split.md) round 5, agnostic review of the round-4 fix, which reintroduced the original defect one variant deeper.
- **A package script is re-parsed by a shell, so appending is not composition.** Flags forwarded through `<pm> run <script>` are concatenated onto a string the shell parses again. The guard must reject not only what starts a new command (`;`, `|`, `&`, newline) but what makes the shell discard the tail: a trailing `#` comment silently swallows every appended flag, and the failure is a clean exit with the framework on its default port. Verify by observing the child's argv (a `printf '%s' "$*"` script), never by asserting on the array the injector produced. Provenance: [366](366-shell-reparse-and-consumer-split.md) round 4.
- **Package scripts run under `sh`, and `sh` is dash on Debian and Ubuntu.** Anything that reasons about how a package manager will parse a script is reasoning about POSIX sh, not about the shell on the author's machine. macOS `/bin/sh` is bash in POSIX mode and accepts bash extensions that dash rejects: `&>` is the live example, where dash backgrounds the command and runs the redirect separately, so appended flags vanish. Exempt only constructs POSIX defines — file-descriptor duplication `2>&1`, `>&2`, `2>&-` — and verify against `/bin/dash` directly, not against the default shell. Provenance: [366](366-shell-reparse-and-consumer-split.md) round 6, caught by CI on ubuntu after passing every local sweep.
- **Classify a subcommand from the CLI's grammar, not from argument positions.** Deciding whether an invocation is a server is deciding what a token *means*, and that is settled by which flags consume the next token. Reading "the first bare positional" makes `vite --mode dev build` a dev server and `vite --config ./cfg.ts` an unknown subcommand — one missing fact, one false positive and one false negative. Record each CLI's value-taking flags from its own option table, and when a CLI's grammar is unrecorded, refuse to classify it once a flag precedes the subcommand rather than guessing. Provenance: [366](366-subcommand-classification-and-flag-arity.md) round 7.
- **An allowlist entry is a claim, and the dangerous direction needs execution evidence.** "This subcommand serves" and "this bare invocation serves" are load-bearing: wrong, they break a working command. An absent entry only costs an injection. Doc prose is enough to *withhold* an entry and not enough to add one — an astro sub-subcommand list taken from a docs page named commands the installed astro does not have, guarded a CLI that validates no unknown flags anyway, and cost a false negative. Provenance: [366](366-subcommand-classification-and-flag-arity.md) round 7.
- **Appending past `--` is not composition either.** Everything after a bare `--` is positional data for the framework, so appended flags are never parsed as options: the dev server keeps its default port and the route 502s, with no error anywhere. Splice before the `--` on argv; a package script carrying its own `--` cannot be reached by appending at all and must be skipped. Extends **a package script is re-parsed by a shell**: that invariant covers what the shell discards, this one covers what the framework's own parser discards. Provenance: [366](366-subcommand-classification-and-flag-arity.md) round 7.
- **Test-shim hermeticity.** A test that shims an external binary (`bun`, `node`, a package runner) guarantees the shim wins over a really-installed binary of the same name; otherwise the real tool shadows the shim and the test passes for the wrong reason. Provenance: [366](366-guard-derived-matrix.md) round 3.

## Verification norms

- A relaxed validator or widened trigger regenerates the verification matrix from the new input domain: enumerate the input classes now reachable and exercise one of each; the bug report's matrix verifies the old fix, not the new code. Matrix cells are derived from the input domain the composed helpers accept, never from the argument positions the new guard inspects: cells derived from the guard under test inherit its blind spot. Provenance: [365](365-risky-suffix-overgeneralization.md) and [366](366-guard-derived-matrix.md).
- Force-red per mechanism, not per fix: delete each mechanism the change introduces separately and require a distinct failure for each. A test that survives the deletion of the data it supposedly pins is asserting a verdict two mechanisms can reach — removing rsbuild's value-flag table broke nothing, because `rsbuild --mode dev build` declines by arity and by the unknown-grammar bail alike. Add the cell where the mechanisms disagree. Provenance: [366](366-subcommand-classification-and-flag-arity.md) round 7.
- A CLI whose package will not install is still verifiable: fetch its tarball from the public registry with curl and read its own option table (`curl -s https://registry.npmjs.org/<pkg>/latest | jq -r .dist.tarball`). A corporate registry answering 401 is a reason to change transport, not a reason to record assumptions as facts. Provenance: [366](366-subcommand-classification-and-flag-arity.md) round 7.
- Helper tests prove the helper; when behavior changes in orchestration, drive and mutate the changed caller. Provenance: [0355](0355-changed-caller-coverage.md).
