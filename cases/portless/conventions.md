# portless review conventions

Project overlay for the [review-gate](../../skills/review-gate/SKILL.md) skill. Harvested from the recorded cases in this directory and from `AGENTS.md` in the portless repo root (primary source of house norms). Surface map added 2026-07-17 from the first maintainer-confirmed external-review miss (PR #363), on a machine with the repository present.

## Surface map

Derived from the "Docs Updates" rule in AGENTS.md: any change that affects how humans or agents use portless (commands, flags, behavior, config) must touch all three documentation surfaces. The `surfaces` gate requires them in the diff or an explicit exemption with a reason.

```surfaces
packages/portless/src/proxy.ts :: README.md, skills/portless/SKILL.md, packages/portless/src/cli.ts
packages/portless/src/cli.ts :: README.md, skills/portless/SKILL.md
packages/portless/src/routes.ts :: README.md, skills/portless/SKILL.md
```

Judgment surface (not blocking, review by hand): `apps/docs/src/app/**/*.mdx`. The web docs mirror README sections (`https/page.mdx` ↔ the "HTTP/2 + HTTPS" README section). AGENTS.md does not list them as mandatory, but when the README gains a behavior sentence, its mirror page probably should too. `gate.sh siblings <keyword>` regenerates this list mechanically.

## House norms

- **Dash style inverts the universal gate.** portless BANS ` -- ` as a dash in prose and PREFERS the em dash (—). The em-dash half of `gate.sh style` does not apply here; the ` -- ` half does.
- **No emojis** anywhere (code, comments, output, docs).
- **`cli.ts --help` is a contract-carrying surface, not a terse listing.** The help text has bolded feature sections ("HTTP/2 + HTTPS (default):", "LAN mode:") with behavior prose. The docs-behavior-parity lens exemption for terse command listings does NOT apply to those sections: silence there about a behavior delta is a finding.
- Package manager: pnpm (npm only in end-user install instructions).
- Boolean env vars documented only as `0`/`1` (code accepts more; the alternatives stay undocumented).

## Subsystem invariants

- **Dual-loopback dialing.** Anything that dials a local service probes the exact host and address family the consumer binds; `127.0.0.1` and `::1` are different answers. An old branch that adds a new dial path copies the assumptions of its era; check which invariants landed on main after the branch was cut (`git merge-base` + `git log <base>..main -- <subsystem>`). Provenance: [288](288-downstream-address.md); PR-staleness mechanism from the #363 competing-PRs case (pending sync).
- **Additive mode composition.** A mode that adds a discovery namespace appends to explicit user configuration, never replaces it. Provenance: [346](346-lan-tlds.md).
- **Config provenance.** A value normalized from multiple loaders carries its origin beside it until presentation; reconstructing origin later produces plausible but false diagnostics. Provenance: [274](274-config-provenance.md).
- **Runtime precedence.** PATH augmentation adds only required tool directories and preserves the caller's runtime precedence. Provenance: [241](241-runtime-precedence.md).
- **Argument boundaries.** Flags injected into a command hidden behind a package script are verified across every runner boundary; correct flags at the outer command can be silently dropped. Provenance: [285](285-package-script-flags.md). Each injected flag is independent: injecting a missing `--host` must not be gated on `--port` also being absent (partial-injection cell). Provenance: [366](366-guard-derived-matrix.md) round 3.
- **Resolution-rule consistency across consumers.** A resolution rule for overlapping entries (longest-match TLD, precedence order) is applied by every path that reconstructs the value from user input, not only the primary resolver: error builders and 404/suggestion text that re-split the input naively produce plausible-but-wrong answers. Provenance: [365](365-risky-suffix-overgeneralization.md) round 3.
- **Daemon emission and one-shot latches.** A user-facing warning/error is emitted on the process the user is attached to (the CLI), not the background daemon whose output only reaches the proxy log; and a "warn once" latch is not consumable by an internal warm-up call (an initial empty sync) before the user-triggered path runs. Provenance: [367](367-daemon-emit-latch.md).
- **Wait ceilings derive from the producer's worst-case cadence.** A CLI-side wait for something a daemon produces asynchronously (a marker file, a state flip, a route reload) sizes its ceiling from every timing constant on the producer's path — debounce **plus** the watcher's fallback poll interval, not just the debounce. `DEBOUNCE_MS = 100` and `POLL_INTERVAL_MS = 3000` live in the same file 550 lines apart; a ceiling that looks generous against the first is guaranteed to expire before the second on any filesystem where `fs.watch` does not fire. Provenance: [367](367-daemon-emit-latch.md) round 4.
- **A wait on a producer first establishes that the producer exists.** Sizing a ceiling correctly only bounds the wait; it does not make the wait end. When the awaited value is published by exactly one process (the daemon writing a status file, a marker, a state flip), every path where that process is absent, dead, or never started pays the full ceiling and then returns the same empty answer it could have returned immediately. Enumerate the producer's liveness cases (not running yet, stopped, stale PID file, crashed mid-run) beside the timing cases, and short-circuit them the way an explicitly disabled feature is already short-circuited. Sharpening the ceiling makes this worse, not better: the better-derived the ceiling, the longer the no-producer path hangs. Provenance: [367](367-daemon-emit-latch.md) round 5, extends **wait ceilings derive from the producer's worst-case cadence**.
- **Test-shim hermeticity.** A test that shims an external binary (`bun`, `node`, a package runner) guarantees the shim wins over a really-installed binary of the same name; otherwise the real tool shadows the shim and the test passes for the wrong reason. Provenance: [366](366-guard-derived-matrix.md) round 3.

## Verification norms

- A relaxed validator or widened trigger regenerates the verification matrix from the new input domain: enumerate the input classes now reachable and exercise one of each; the bug report's matrix verifies the old fix, not the new code. Matrix cells are derived from the input domain the composed helpers accept, never from the argument positions the new guard inspects: cells derived from the guard under test inherit its blind spot. Provenance: [365](365-risky-suffix-overgeneralization.md) and [366](366-guard-derived-matrix.md).
- Helper tests prove the helper; when behavior changes in orchestration, drive and mutate the changed caller. Provenance: [0355](0355-changed-caller-coverage.md).

## Gate-miss ledger

- **2026-07-25 — PR #367 round 5, self-caught: the round-4 fix for the wait ceiling made the no-daemon path hang for the full 4.1s, worse than the 1.62s it replaced.** Raising `HOSTS_SYNC_STATUS_WAIT_CEILING_MS` to `DEBOUNCE_MS + POLL_INTERVAL_MS + 1000` correctly cleared the daemon's fallback poll, but the daemon is the only process that publishes an outcome. Registering an alias before starting the proxy has no producer, so the wait could not end early and burned the whole ceiling on a routine command. Measured on the built CLI with an isolated state dir: no daemon 4.202s, stale PID file 4.2s, against 0.155s with the daemon alive. Neither `gate.sh timings` nor the wait-ceilings invariant covers this: both reason about how long to wait, and the defect is whether to wait at all. Fix-induced regression, same shape as the 2026-07-17 #365 gate-fix over-reach entry, where the fix for a finding generalized past the finding. Closed by: the **a wait on a producer first establishes that the producer exists** subsystem invariant. Deliberately not a deterministic gate: recognizing that a value has exactly one publisher requires reading the subsystem, not matching a pattern, so this stays in step 3's model reconstruction. Fixed in `c826d10` (0.053s no daemon, 0.060s stale PID, 0.166s daemon alive with the warning still delivered).
- **2026-07-25 — PR #367 round 5, self-caught: a semantic collision with an unlanded branch that no CI can see.** A separate branch (`railly/hosts-atomic-write`) widens what `syncHostsFile` returning `false` means, adding a read-failure class to what was a write-only failure. #367 gives that same boolean an English diagnosis and a remedy on five surfaces: `Could not write /etc/hosts; hostnames may not resolve. Run: portless hosts sync`. The branches touch disjoint files (`hosts.ts` vs `cli.ts`/`cli-utils.ts`/docs), merge clean, and both suites stay green, so the wrong diagnosis and the non-working remedy are invisible to every automated check. Surfaced by step 3's model reconstruction, not by any gate; confirmed by merging both in a scratch worktree and composing the real helpers against an unreadable hosts file. Open question at record time: which lands first, and who owns the wording change. Recorded because the class generalizes — **a diff that widens the meaning of a value collides with any unlanded diff that gives that value user-facing prose**, and file-level disjointness is exactly why nothing catches it. Case: [369](369-partial-write-orphan-block.md).
- **2026-07-24 — PR #367 round 4, ctate: the marker poll expires after 1.5s while the daemon's watcher fallback runs every 3s, so warnings are missed and later surface stale.** The gate's round-4 run reported the stale-marker symptom (F3) but justified its reachability as an edge case (CLI interrupted mid-poll, concurrent poll losing the race) instead of reading the producer's own timing constants: `HOSTS_SYNC_MARKER_POLL_CEILING_MS = 1500` versus `POLL_INTERVAL_MS = 3000` (cli.ts:141), which makes the miss routine wherever `fs.watch` does not fire. The diff's own comment sized the ceiling against `DEBOUNCE_MS` (100) and never looked at the fallback interval. Closed by: `gate.sh timings` (enumerates every larger timing constant a new ceiling must clear) + the **wait ceilings** subsystem invariant + the producer-cadence clause on the cancellation-and-timeout-hygiene lens.
- **2026-07-24 — PR #367 round 4, ctate: successful alias registration always waits the full timeout (measured 1.62s with hosts sync disabled).** Caught independently by the gate in the same round (F2, measured 1.596s/1.613s) via the dogfood pass. Not a miss; recorded because it is the second confirmation that driving the artifact, not reading it, is what produces timing findings.

- **2026-07-22 — PR #365 round 3, ctate: the 404 suggestion does not use longest-match ordering for overlapping TLDs.** With `example.com` and `dev.example.com` both registered, a request to `missing.dev.example.com` suggests `portless missing.dev your-command`, registering the wrong hostname set. The resolver applied longest-match; the suggestion builder re-split the host with a naive rule. No lens required every consumer of the resolution rule to apply it. Closed by: **Resolution-rule consistency across consumers** lens + subsystem invariant.
- **2026-07-22 — PR #367 round 3, ctate: the warning is emitted by the daemon (proxy log only) and the initial empty sync consumes the warning latch, so route registration stays silent for the user.** Two runtime classes (emission-channel boundary + one-shot latch consumed by a warm-up call) that the 07-20 #367 doc-sibling entry did not touch. Closed by: **Emission channel and one-shot latch reachability** lens + daemon-emission subsystem invariant. Case: [367](367-daemon-emit-latch.md).
- **2026-07-22 — PR #366 round 3, ctate: quoted `&` characters and shell redirections are incorrectly treated as compound scripts.** Extends the 07-20 glued-operator/newline miss with more adversarial detector forms (quoted metacharacters, redirections the shell still honors). Closed by: new-domain-matrix detector cells now include quoted metacharacters and redirections, not only bare operators.
- **2026-07-22 — PR #366 round 3, ctate: an existing `--port` prevents the missing `--host` from being injected.** The flag-injection matrix tested all-present/all-absent but not the partial cell where one target flag is present and its sibling absent. Should have been caught by the guard-derived-cells norm applied to the injection matrix; it was not. Closed by: partial-injection cell added to the new-domain-matrix flag-injection axis + argument-boundaries invariant.
- **2026-07-22 — PR #366 round 3, ctate: the new integration tests fail when Bun is installed beside Node because the real binary shadows the test shim.** Test-harness hermeticity: a PATH-prepended shim can be shadowed by a really-installed binary, so the test exercises the wrong tool. Closed by: **Shim hermeticity** lens + test-shim-hermeticity verification invariant.

- **2026-07-20 — PR #367 (#364), human-caught: cli.ts `--help` auto-sync prose block and the canonical `Auto-syncs ...` lines in README/SKILL/apps-docs stayed silent about the new hosts-sync-failure warning, while the same warning landed in one other section of each of those files.** Root cause is systemic, not a keyword choice: both `surfaces` and `siblings` are **file-level** (`check_siblings` flags a file only when it mentions the keyword AND is absent from the diff). Every relevant file was in the diff for one passage, so both gates passed while sibling passages inside them stayed stale. Distinct from the #363 cross-file miss (a file entirely absent from the diff). Caught by Hunter, not the gate. Closed by: Doc-sibling sweep made line-level within diffed files (catalog + `check_siblings` now greps the keyword on untouched lines of diffed files), and the docs-behavior-parity "walk passages, not files" clause.
- **2026-07-20 — PR #365, ctate: 248–253 char hostnames fail HTTPS cert generation because generated paths exceed filesystem limits.** new-domain-matrix fired and caught two length bugs (parseHostnames overlap, 253-char composed hostname) but stopped at the DNS-length invariant; it never handed off to the cert-generation consumer's own substrate limit (`NAME_MAX` ~255 bytes/path component). A 253-char hostname is valid DNS and invalid as a filename. Seam between new-domain-matrix (length axis) and substrate-verification (filesystem effect). Closed by: new-domain-matrix substrate-not-semantics clause.
- **2026-07-20 — PR #365, ctate: docs claim custom TLDs work across LAN/tailnet, but `--lan` forces `.local` and normal mode binds loopback-only.** docs-behavior-parity checked whether the new behavior got documented, not whether a pre-existing claim was falsified by the widened domain (inverse direction); and PR-staleness was not run against the loopback-binding hardening the branch predated. Closed by: docs-behavior-parity inverse-direction clause + PR-staleness on the binding subsystem.
- **2026-07-20 — PR #366, ctate: compound scripts with a glued operator (`vite dev&&node`) or a newline separator bypass the compound-script skip guard.** The 2026-07-17 guard-derived-cells norm was applied to the reused helper but not recursively to the fix's own newly-added guard (the operator detector): its cells inherited the detector's whitespace-tokenization assumption. Closed by: new-domain-matrix guard-recursion clause (a detector the fix adds is itself an artifact under test).
- **2026-07-17 — PR #365, gate-fix over-reach (caught by human review, not a gate).** The review-gate correctly flagged that `RISKY_TLDS` exact lookup never warned for multi-segment TLDs, but the applied fix suffix-matched every risky entry — making the flagship documented workflow (`--tld dev.example.com`) warn about DNS leaks on every proxy start. The warning classes needed the same domain analysis as the code: tree-wide risks (`local` mDNS, `dev`/`app` HSTS preload) suffix-match; ownership-class TLDs stay exact. Lesson for the gate: when a finding's fix touches a warning/error taxonomy, classify each entry's failure mode before generalizing the match rule. Provenance: [260](260-multi-segment-tlds.md).

- **2026-07-17 — PR #366, bot review finding: runner-wrapped build scripts bypass the `rawScript[1]` build guard.** The new-domain matrix lens ran and probed build cells (`vite build --watch`, `next build`) but enumerated them from the guard's own inspected position instead of from the domain `findFrameworkBasename` accepts (runner wrappers: npx, bunx, pnpx, dlx, exec — a class #150 had already named in the same file). `"dev": "bunx vite build"` got dev-server flags forwarded; confirmed by repro. Closed by: guard-derived-cells rule added to the verification norm above and to the lens entry in the catalog. Case: [366](366-guard-derived-matrix.md).
- **2026-07-17 — PR #366, self-caught gate bug: `gate.sh siblings` returned a false PASS on an invocation error.** A stray literal `--` passed as a pathspec matched no files, so zero hits read as "no file mentions the keyword" right after the diff itself added the keyword to three files. A deterministic gate whose expected state is "hits exist" must fail loudly when its search space is empty. Closed by: `gate.sh` now errors when the pattern appears in the diff's added lines but the repo-wide search returns nothing.
- **2026-07-17 — PR #363, maintainer doc nit: the cli.ts help does not mention WebSocket over HTTP/2.** Two gates should have caught it: (1) `surfaces` — never ran, because this file had no surface map yet (the absence was recorded in the report, which changed nothing); (2) docs-behavior-parity — ran, but the terse-listing exemption was misapplied to the help's "HTTP/2 + HTTPS" section, which carries behavior prose and whose sibling README section did gain the new sentence. Both causes closed: the surface map above makes the check deterministic, and the cli.ts-as-contract norm corrects the lens application. Follow-on: the `siblings` gate (`gate.sh siblings "HTTP/2"`) was added and force-red'd against this exact diff; it flags cli.ts and the apps/docs pages.
