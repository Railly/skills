# wterm conventions

Compiled from `AGENTS.md`, `CONTRIBUTING`-equivalent prose, and `.github/workflows/ci.yml` in `vercel-labs/wterm`. Bootstrapped 2026-07-31 during the review gate on PR #98.

## Surface map

Every line: when the diff touches the left, the right must be updated or exempted with evidence.

```surfaces
packages/@wterm/*/package.json:scripts  :: packages/@wterm/*/README.md
packages/@wterm/ghostty/scripts/**      :: packages/@wterm/ghostty/README.md, apps/docs/src/app/ghostty/page.mdx

examples/*/**                           :: examples/*/README.md
packages/@wterm/core/package.json:version :: all @wterm/* package.json (via `pnpm sync-versions`)
```

AGENTS.md states the docs rule for "any user-facing change (new feature, option, API change, bug fix, etc.)". Bug fixes are named explicitly, so a fix that makes a documented option actually work still runs the surface check; it exempts only after the surface is read and found already correct.

## House norms

- Formatter is **prettier**, not biome. `pnpm format:check` runs `prettier --check "**/*.{ts,tsx,js,jsx}"`. Running biome reformats and reorders imports across untouched files and produces a diff the repo does not want. (Gate-miss 2026-07-31.)
- No linter enforces `no-explicit-any`. Tests use bare `as any`. A `biome-ignore` comment is noise here.
- Tables in MDX use `<table>` HTML elements, never markdown table syntax.
- Dev servers use `portless <name>.wterm`, never a `--port` flag, and portless is never a project dependency.
- Releases are manual and maintainer-controlled. A feature PR does not touch `CHANGELOG.md` or versions.
- Dependencies are added with `pnpm add`, never by hand-writing a version.
- Em dashes are established prose punctuation in this repository, including every root README feature bullet. The generic no-em-dash style check is exempt when a new line follows that existing form.

## Subsystem invariants

- **The committed wasm is the artifact under review, but it must be rebuilt from the current source before tests are trusted.** `packages/@wterm/core/wasm/wterm.wasm` is built and diff-checked by CI; `packages/@wterm/ghostty/wasm/ghostty-vt.wasm` is **not**. A Zig change in `@wterm/ghostty` is not verified by CI until the binary is rebuilt and committed. A test loading an older correct binary can stay green while the current Zig source is broken, so source-changing review must rebuild first, then run the real-WASM regression and check the rebuilt artifact into the diff.
- **Both ghostty wasm builds are byte-reproducible across host platforms.** A container build equals a host build, so a diff-check is meaningful and a mismatch means a real source/binary drift.
- **A DataView over WASM memory is invalidated by any growth, not only by a write.** `GhosttyCore` caches views for the viewport and for one scrollback row. A cache hit can outlive a grow triggered by an unrelated read, so every path that returns a cached view must compare `view.buffer` against `exports.memory.buffer` before handing it back. Early-return-on-cache-hit is the shape that reintroduces this. (`@wterm/core` carries a dedicated `wasm-memory-growth.test.ts` for the same class.)
- **`RenderState` covers the active area only.** Anything reading history (scrollback) must read the page list directly and cannot reuse `RenderState`-derived helpers. This is why cell encoding is duplicated between `get_viewport` and `get_scrollback_line`; a change to the cell contract belongs in both.
- **`RenderState.Cell.style` is undefined unless the raw cell carries a non-default `style_id`,** and the style array is reused across render passes, so reading it ungated resurfaces another screen's style. See case `0086-style-id-stale-across-screens.md`.
- **Scrollback offset 0 is the row directly above the active area**, and the length accessor returns the row's grid width, not its trimmed text length. The renderer uses that length as the cell-count bound. Both conventions are set by `@wterm/core`'s `WasmBridge` and any second core must match them.
- **A bounded scrollback DOM is a moving window, not the retained history itself.** Browser find and accessibility inspect mounted rows only. Native selection may temporarily widen the window so the selected range stays mounted. Any public claim that find, accessibility, or the DOM covers all retained history is false once virtualization is enabled.
- **A renderer rebuild can synchronously destroy the scroll geometry that defines the user's logical position.** `Renderer.setup()` clears and recreates the DOM, so the browser may clamp `scrollTop` to zero before the next frame. Capture a non-bottom logical offset before setup, preserve the first offset across coalesced resizes, render the rebuilt spacers from that pending value, and restore it only after the new geometry exists. The opposite direction matters too: bottom-anchored users must continue following the bottom instead of restoring an obsolete numeric offset.
- **Scrollback rollover identity requires a monotonic discarded-row signal, but optional means the fallback must remain correct without it.** Built-in and Ghostty cores expose the cumulative number of rows pruned from the oldest end so the DOM can preserve row identity and adjust `scrollTop`. A third-party core without that optional method cannot provide exact rollover anchoring, but the renderer must re-read its visible window instead of reusing rows solely because the retained count stayed constant.
- **Browser E2E must build the package artifact it imports and must not reuse an unrelated server.** The Vite fixture resolves `@wterm/dom` from `dist`, so Playwright's web server command builds `@wterm/dom` before the example. Port 4173 reuse is disabled; an occupied port is an explicit setup failure, not permission to test whichever process already owns it.
- **Debug exposure is not fixture readiness.** `__wterm` is published during `WTerm.init()`, before the example attaches its shell and writes the greeting. Browser tests that mutate the core directly must first wait for an observable post-attach signal, otherwise the fixture's initial write can race the test and add one unrelated scrollback row.
- **Mouse coordinates are measured from rendered active cells, not from the root box.** The `.wterm` root's default padding is outside the grid, scrollback rows extend `.term-grid` above the active viewport, and a fixed-column terminal can leave unused width inside the root. Coordinate conversion must subtract content offsets and divide by measured cell dimensions (or the active-row box), without scaling over padding, scrollback, a scrollbar, or spare CSS width. The opposite error directions are reachable: including padding shifts interior cells up/right, history geometry shifts rows with scroll position, and scaling 80 rendered columns across a wider fixed root reports a smaller column than the cell under the pointer.
- **Mouse capture belongs to the terminal element's browsing context and to the full pressed-button set.** Global drag/up listeners use `element.ownerDocument` or its `defaultView`, arm only after a press is actually emitted, and remain until `event.buttons` reaches zero. The opposite directions are both reachable: a top-window listener misses iframe releases, while arming before a valid press can emit an orphan release later.
- **Mouse refocus precedes mouse protocol delivery, unsupported buttons are rejected, and tracking retains a selection escape hatch.** Focus the hidden textarea on `mousedown` before emitting a mode-1004 focus report and the mouse press; a `click` handler runs after press/release and may never run for a drag ending outside. Mouse buttons outside the SGR encoder's supported set must return without capture or output, never fall through to button code 0 (left). Because native text selection is a product contract, tracking mode must leave a deliberate modifier path that does not emit/prevent the mouse event; forwarding Shift only as an SGR modifier removes the browser selection path.
- **Input-mode state crosses every `TerminalCore` implementation before the DOM consumes it.** Built-in and Ghostty cores expose the same mouse/focus modes from their committed WASM artifacts; optional interface methods preserve third-party source compatibility but absence means the DOM deliberately treats that core as not supporting the feature.
- **Kitty keyboard flags form independent protocol states, not one all-flags mode.** Every meaningful flag combination must be exercised independently. In particular, `report event types` without `report all keys` keeps plain unmodified text on the legacy text path and must not emit a matching release escape, while modified text keys may still report event types.
- **Host-owned presentation state must cross the adapter boundary before a core can answer presentation queries honestly.** OSC 10 and OSC 11 replies must reflect the foreground and background the browser host actually renders, not an adapter constant. Drive configured defaults, runtime set, reset, query ordering, and BEL/ST framing through the committed WASM.
- **Synchronized-output recovery is one atomic state transition, not a paint exception.** The timeout owner must both leave authoritative mode 2026 and flush the pending frame. Flushing without clearing the mode re-holds every later write; clearing without flushing leaves the completed frame hidden until another render producer happens. The recovery clock starts at BSU, ordinary payload writes cannot postpone it, and every observed generation change while held must cancel the inherited timer and arm a full new deadline. After recovery, a later BSU must begin a fresh atomic hold even if no ESU arrived for the expired block. A generation regression test must send real `ESU → BSU` bytes through the committed WASM; manually changing a mocked generation number does not exercise the parser/core/DOM boundary. This invariant runs in both directions whenever the DOM scheduler and terminal core share ownership of a mode.
- **Final-grid equality does not prove atomic rendering.** Synchronized output is temporal: a broken adapter can paint every intermediate update and still finish with zero mismatches. Count render callbacks inside the block, force the core's synchronized-output signal off and require intermediate renders to return, then restore and require one closing paint. A final screenshot is supporting evidence only.
- **Application callback failure is tracked by presence, not by the thrown value.** JavaScript permits `throw undefined` and `throw null`; response draining must preserve the exact first thrown value while continuing parser chunks and scheduling the completed render. A nullish value cannot double as the “no error” sentinel, and each named continuation seam needs its own force-red assertion.
- **Built-in OSC 8 indices live for the host terminal lifetime, not the current RIS epoch.** RIS preserves scrollback and is invisible to the JS link cache, so resetting and reusing numeric indices aliases old cells or cached metadata to new destinations. Reset the hyperlink table only when host `init()` also clears scrollback and the JS cache.
- **Logical scroll anchoring has one owner.** When the host subtracts discarded rows from `scrollTop` to preserve row identity, disable native browser scroll anchoring on that scroll owner. Otherwise frame-separated rollover can apply the same compensation twice even when a batched test passes.
- **A browser reclamp caused by WTerm's own DOM mutation does not transfer scroll ownership to the user.** Virtualization can temporarily shrink `scrollHeight`, clamp an accepted programmatic `scrollTop` to the new maximum, and emit the `scroll` event later. While WTerm is following output, an event that lands at the current bottom preserves follow state even when it no longer matches the previously accepted numeric position. The opposite direction remains user-owned: once the position is outside the bottom threshold and outside the accepted programmatic tolerance, follow state is cleared and rendering is rescheduled.
- **Hyperlink bounds cross every retaining layer.** A fixed core identity table does not bound an adapter cache, and a silent saturation outcome is not graceful rejection. Each table or cache declares its lifetime, capacity, observable saturation signal, and recovery boundary.
- **Malformed or truncated OSC 8 input clears the active link.** Ignoring an invalid open while a prior link is active fails open and stamps later output with the previous destination. Every parse rejection path must leave subsequent cells unlinked.
- **Terminal hyperlinks use one stable activation contract across mouse modes.** Plain pointer clicks remain terminal interaction whether or not SGR mouse tracking is active. Command-click on macOS, Control-click on Windows and Linux, and keyboard activation remain browser-link escape hatches. A modified hyperlink press must not emit a mouse report before navigation. The opposite direction matters too: a plain click must still reach mouse tracking instead of being swallowed merely because the cell carries OSC 8 metadata.
- **Scratch-buffer growth is fail-closed after allocation.** A failed Ghostty scratch-buffer realloc leaves a zero pointer; the caller must stop before retrying or decoding, never read from WASM address zero.
