## Subsystem model

The terminal application writes negotiation sequences into the selected core. Each core owns the active Kitty stack and exposes the current five-bit value. `InputHandler` reads that value for every browser event and delegates byte encoding to one pure DOM module. Built-in Zig and Ghostty Zig answer protocol queries from the same state their mutation paths update. The committed WASM binaries are the runtime boundary.

Adjacent layers reviewed:

- Parser recognition to stack mutation and query response.
- Primary and alternate screen ownership.

- Optional third-party and older-WASM fallback.
- Browser keydown, repeat, keyup, shortcut, and composition pairing.
- Key identity, keypad identity, modifiers, alternates, and associated text.
- User documentation and browser limitations.

## Findings found and fixed

1. Functional key names could become associated text.
   - Cause: `KeyboardEvent.key` values such as `Enter` and `ArrowUp` were iterated as text.
   - Fix: associated text is limited to printable single-codepoint entries.
   - Evidence: `kitty-keys.test.ts` asserts Enter and ArrowUp exact bytes.

2. Browser-owned presses could produce orphan Kitty releases.
   - Cause: keyup re-evaluated current modifiers after copy, paste, Command shortcuts, or composition consumed keydown.
   - Fix: `InputHandler` tracks suppressed physical key identities and clears stale suppression on a later terminal-owned keydown.
   - Evidence: shortcut, composition, and lost-keyup regressions in `input.test.ts`.

3. Built-in push and pop extra-parameter behavior initially diverged from Ghostty.
   - Cause: the first parity fix treated extra parameters as rejection.
   - Fix: match Ghostty 1.3.1 exactly. Push defaults flags to zero; pop defaults count to one.
   - Evidence: Zig regression `kitty keyboard push and pop default extra parameters`.

4. Keypad Enter and NumLock-off navigation could lose keypad identity.
   - Cause: recovery handling classified `NumpadEnter` as ordinary Enter, and physical numpad codes were used without the navigation value in `key`.
   - Fix: encode keypad Enter as 57414 and resolve keypad navigation from the `code:key` pair.
   - Evidence: exact vectors for NumpadEnter, Numpad1/End, and Numpad8/ArrowUp.

5. An older custom WASM binary could crash despite the optional `TerminalCore` method.
   - Cause: the TypeScript adapter existed but called a missing WASM export unconditionally.
   - Fix: both adapters treat missing Kitty exports as flags zero.
   - Evidence: built-in and Ghostty older-WASM regressions.

The audit was split into focused passes for protocol state, DOM input, WASM bridges, and `.decisions.tsv`. Candidate findings were verified before disposition:

- Stack wrap and oversized pop: refuted. The circular eight-entry behavior is an accepted parity contract executed against pinned Ghostty 1.3.1 and covered by the built-in regression.
- Parser support for `<` and `=`: refuted. Those markers are consumed only for final `u`; no other `csi_private` consumer changes behavior.
- Repeat handling without `KITTY_REPORT_EVENTS`: refuted. `encodeKittyKey` maps repeat to event type zero unless the negotiated bit is present, so it emits press-compatible bytes.
- Stale shortcut suppression: refuted. A later terminal-owned keydown deletes the matching stale suppression before dispatch.
- TypeScript/WASM compatibility and active-screen query path: passed with no code findings.
- Trail audit: one valid non-blocking flag. Independence from PR #119 is explicitly recorded as an assumption, not established merge-order evidence. Two other trail flags were refuted because they misread the scope of the append-only superseding rows.
