# Native boundary evidence

The WebMCP upstream explainer is the independent registration/cleanup oracle (local captured README at /tmp/badge-webmcp-readme.md). The installed native Chromium and agent-browser are the actual producer and consumer, not a JavaScript WebMCP shim.

Production build: 73 native-tool calls test discovery, all 17 catalog directions, schema, photo example, atomic front/back/material changes, invalid QR rejection without state change, locks/visibility/undo, metadata, invalid URL rejection, true raster-byte extraction/import, artwork, local saves/load/reload, PNG/JSON files, mobile, and leave/return registration cleanup. All pass. `browser-checks.json`, `exercise.py`, rendered screenshots and actual downloads reside in the v17 evidence folder.

60 fault-path calls force a held sample-image fetch twice, concurrent mutation refusal, explicit cancellation with no portrait commit, immediate retry, a ten-second fetch timeout, manual-UI stale-edit rejection, IndexedDB open failure with honest failure receipt and immediate successful retry, navigation during the held fetch, manual controls after simulating a missing document.modelContext, and a forced UI publication failure after IndexedDB commit followed by a same-ID retry without duplicates. Profile persistence refusal was also forced after image assignment: the usable image stays in-session with a storage warning; restoring storage and immediately retrying clears the warning. All pass on the production build. `fault-checks.json` and `faults.py` preserve the scenario.

Host finding: a temporary native registered probe showed callback options undefined in this Chromium implementation. `agent-browser webmcp cancel` marked the transport cancelled while work continued until the fetch timeout. The app now offers `badge_cancel` with a specific operation ID and waits for cleanup. It does not claim that every browser forwards invocation AbortSignal. This is a compatibility limitation with an explicit working path, not a hidden success claim.

Mutation evidence: removing assertLocks at its production call site makes the lock rejection test fail for the intended reason. Bypassing requireRevision in the production React hook makes a real native call accept a stale edit; the browser assertion fails. Both sources restored exactly and the same checks pass. Assertions observe state and actual result rather than the validator's own derived expectations.

Scope: these checks prove the declared paths on installed Chromium/macOS and the local production build. They do not claim paid image-model execution, all browser engines, all possible asynchronous interleavings or phone GPU performance. The image transfer roundtrip used the fictional sample and performed no paid inference.
