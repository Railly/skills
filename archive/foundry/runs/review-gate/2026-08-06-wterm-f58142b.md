## Findings

### High — ordinary payload can postpone recovery forever

`WTerm.write()` calls `_scheduleSynchronizedOutputFallback()` for every write while mode 2026 is active (`packages/@wterm/dom/src/wterm.ts:159-162`), and that helper cancels and recreates the timer (`:223-230`). The written synchronized-updates contract starts the clock when BSU is handled and extends it only for another BSU. In a built-package drive with committed WASM, `BSU + A`, 900 ms, then ordinary `B` still had no paint at 1,002 ms from BSU. A continuously emitting producer that loses ESU can therefore keep output hidden indefinitely.

The added test encodes the bug as intended behavior: it calls `term.write("continued")` rather than sending another BSU. Documentation repeats that widened semantics as “one second of inactivity.”

### High — a fresh BSU after timeout does not begin a new atomic block

After fallback, `_synchronizedOutputTimedOut` remains true until the core reports mode 2026 false (`packages/@wterm/dom/src/wterm.ts:160-165`). The fallback never ends authoritative mode 2026, so another BSU leaves the boolean true and the local bypass latched. Driving `BSU + A`, timeout, then `BSU + B` painted `B` immediately instead of holding it until ESU. Recovery therefore still is not a completed mode transition; it permanently disables atomic holds until the stale block eventually receives ESU/reset.

This is the unresolved adjacent direction of the prior high finding: later ordinary writes now paint, but the timed-out block still owns the core state and masks future begins.

### Medium — a throwing response callback skips timeout and render bookkeeping

`write()` drains host responses before evaluating synchronized state (`packages/@wterm/dom/src/wterm.ts:158-168`). If public `onData` throws, `_drainResponses()` propagates immediately and the function never arms the synchronized fallback or schedules a render. A built-package/committed-WASM drive of `BSU + X + CPR request` with a throwing callback confirmed `_synchronizedOutputTimer` remained null. If the caller catches the callback failure, the partial block has no recovery deadline from that write.

Open PR #105 contains a more defensive response-drain design, but it is not part of this exact head and cannot exonerate PR #106.

### Medium — required feature surfaces remain incomplete

The new DOM README paragraph and API-reference paragraph are present, and the prior getter-documentation finding is fixed. However, `src/terminal.zig` changed without the root README required by the project surface map, and both canonical feature lists still describe only ordinary dirty-row `requestAnimationFrame` rendering: `README.md:19-24` and `apps/docs/src/app/page.mdx:19-23`. The newly added timeout prose is also behaviorally inaccurate because ordinary writes currently reset the clock.

Navigation and page-title files are exempt: no page was added or renamed.

## Subsystem model and adjacent layers

The in-process path is transport/application → `WTerm.write()` → built-in `WasmBridge` → Zig streaming parser and authoritative mode 2026 → `WTerm` timeout/RAF scheduler → DOM `Renderer`. Host responses leave through synchronous `onData`; resize independently mutates grid and renderer shape; destroy owns timer and RAF cancellation. Alternative cores implement the shared `TerminalCore`, but synchronized-output capability is optional.

The latest fix assumes that “timed out” can be represented as a DOM-local bypass while the core stays active. The adjacent layers that assumption leaves incorrect are timer origin (BSU versus any payload), recognition of a later BSU, and exceptions from the response callback before scheduling.
