## Severity findings

### P1 — Mouse capture breaks across the terminal boundary

`packages/@wterm/dom/src/input.ts:130-132,237` listens for press, move, and release only on the terminal element and does not remember where a pressed drag began. Forced event topology showed both broken directions:

- press on the terminal, release on `document` -> only `ESC[<0;2;2M`, no release;
- press outside, enter terminal with `buttons=1` -> orphan `ESC[<32;2;2M` drag.

This leaves TUI applications in a held-button state after the pointer exits the element and sends unsolicited drags when a browser drag enters it. Use pointer capture or document/window move/up listeners armed by an in-terminal press, and release/cleanup them on up, cancel, blur, and destroy. The bot follow-up test exercises only synthetic moves already targeted at the element, so it does not cover this topology.

### P1 — Ghostty-backed terminals silently lose the new feature

`packages/@wterm/core/src/terminal-core.ts:55-57` makes the new mode accessors optional; `InputHandler` interprets absence as disabled. `GhosttyCore`, advertised as a drop-in `TerminalCore`, implements none of them, its Zig adapter exposes only cursor-key/bracketed-paste/alt-screen modes, and the committed Ghostty WASM has no mouse/focus exports. Therefore a Ghostty-backed `WTerm` can parse 1000/1002/1004/1006 internally while `@wterm/dom` emits no mouse or focus reports.

Extend the Ghostty WASM adapter and `GhosttyCore`, or explicitly narrow/document the feature to `WasmBridge`; making the methods optional preserves source compatibility but silently breaks behavioral substitutability.

### P1 — Scrollback corrupts mouse row coordinates

`Renderer.syncScrollback` inserts history rows into `.term-grid` before active rows, while `InputHandler` at `input.ts:239-260` scales `clientY` across the full `.term-grid` rectangle and clamps it to `bridge.getRows()`. Once scrollback is rendered, that rectangle is taller and shifted relative to the active viewport; scrolling changes which history/active row is under the pointer without changing the formula.

A forced 80x40 active grid with an 800px `.term-grid` rect encoded a click at y=410 as active row 21. Coordinate conversion needs the active rows/visible viewport plus scroll offset, not the history-containing grid box.

### P2 — Public docs are missing and one claim is now false

No README or docs page changed. `packages/@wterm/core/README.md:24` still tells users to choose Ghostty for mouse tracking, while the built-in committed WASM now provides it. The WasmBridge method table omits `mouseTracking`, `mouseSgr`, and `focusEvents`, and `@wterm/dom`/web docs do not describe automatic SGR mouse and focus PTY reports. This violates the repository's user-facing-change documentation rule.
