## Claim and supported environment

A4 and the changed core README/API prose claim rejection of decoded __proto__, constructor and prototype path tokens in core path utilities, state stores and core SpecStream, including both path and from before compound mutation. The protected property is integrity of prototypes or data outside the application-provided JSON state/spec graph, and non-disclosure through reserved-token traversal. The modeled lower-trust party supplies serialized paths, patch operations and JSON values, such as an AI/spec producer or a caller whose data is passed into these library APIs. It has not been granted arbitrary JavaScript execution or direct access to global prototypes.

The library itself is not a service, credential store or authorization system. No remote unauthenticated endpoint, shared-tenant server, privileged persistence callback or resource-availability SLA was supplied. Data in the provided state/spec and unrestricted stream-selected element definitions are already under the respective caller/producer's authority. Operators choose state, initial objects, adapter callbacks and installed code. Same-process arbitrary-code operators already have prototype access and are not modeled as lower-trust attackers.

A1-A3 and whole-renderer rejection/notification semantics are not automatically security properties. In particular, a literal universal claim that every renderer rejects every reserved token is false: the legacy React stream dispatcher has separate logic. This is documented below, not concealed by the security pass. The security conclusion is not an RFC conformance, application authorization, complete package safety or merge-ready verdict.

## Trust map and actual wiring

Assets: Object/Array/Function prototype integrity; state outside a supplied JSON graph; store snapshots; externally owned adapter state; trusted application callbacks and component registry code.

Boundaries:

1. Lower-trust JSON path or wire patch to core object traversal/mutation. The caller may mutate supplied state, but not acquire a reference to shared prototypes by reserved-token traversal.
2. Core accepted mutation to host-owned store publication. Core controls validation and decides whether to notify/call setSnapshot; the host already controls callback code. A false callback record alone does not establish unauthorized persistence.
3. Stream JSON to legacy renderer dispatch. The producer already chooses root, state and element definitions. A prototype on its local element dictionary is distinct from Object.prototype or another tenant's state.
4. Host-supplied non-JSON objects and callbacks to runtime behavior. Accessors, proxies, custom prototype graphs and same-process code are higher-authority inputs, not representable by a JSON stream alone.

Definitions, exports and callers were distinguished:

- types.ts:272-301 unescapes JSON Pointer tokens once and checks the decoded segments. JSON string Unicode escapes are decoded earlier by JSON.parse. Pointer ~1 does not introduce a second traversal separator; ~0 is not decoded recursively.
- types.ts:307-362 readByPath blocks reserved tokens before traversal. types.ts:418-541 validates mutable writes before parent creation. types.ts:578-635 blocks removal before traversal.
- types.ts:644-750 stages a move with Object.create-backed local clones. types.ts:880-887 guards both path and from before read/staging; source existence is checked before mutation. For ordinary JSON input the rejected token cannot enter the staged prototype-backed machinery.
- state-store.ts:72-123 guards immutable writes before cloning; :133-189 and :214-251 enforce no-op publication rules for stores/adapters.
- index.ts:35-66 exports public core functions; store-utils.ts re-exports immutableSetByPath/createStoreAdapter. Those are exports, not independent runtime consumers.
- types.ts:949-950 applySpecPatch delegates; compileSpecStream (:1086-1099) and createSpecStreamCompiler (:1150-1213) are real parsed-wire callers. The latter records parsed patches even when rejected, which is not an authorization assertion.
- applySpecPatch also has real callers in Ink, devtools stream-tap, and React/Solid/Vue/Svelte message/mixed-stream paths. These inherit core token guards. This is static call-graph evidence, not a claim that every renderer runtime was tested.
- Legacy useUIStream uses a distinct applyPatch in React hooks.ts:167-204, called at :339/:354. Analogous dispatch exists in React Native, Solid, Vue and Svelte. React state subpaths go through core; direct element-key writes at :89-107 do not. Six caller files are byte-identical at base/head (caller-base-identity.json), though changed core results can still introduce correctness regressions.
- React-state index.tsx:156-171 constructs onStateChange records from submitted entries and the previous snapshot, separately from the core's accepted-write set. This is the F2 owner.

## Candidate chains and classifications

SEC-001, informational, out_of_scope_hardening (non-blocking evidence of the in-scope protection, not an outstanding hardening request): JSON producer controls path/from -> public reads/writes/stores/parsed SpecStream are reachable -> reserved decoded token would select a shared prototype -> exact-head core rejects before traversal, clone, mutation or publication -> no new cross-authority read/write observed. Rejection was checked on direct exact-head source and both existing public ESM/CJS builds. All global prototype descriptors remained unchanged. Confidence high within the stated JSON/API boundary. No remaining vulnerability severity assigned.

SEC-002, non_security_defect, unrelated_bug: F1. A stream producer controls malformed move/copy paths -> actual legacy useUIStream dispatcher reads/removes/writes separately -> rejected destination loses a source, or rejected source becomes an own undefined destination -> the changed data is in the producer-controlled spec/state -> no outside graph, protected principal or additional privilege is demonstrated. Existing numeric-token probes are reused as historical evidence; new reserved-token probes characterize the same missing validation propagation. Blocking or repair decisions belong to correctness review. Confidence high in the defect, not in any security impact. To elevate this, evidence must show a supported restricted patch producer crossing into state it could not already remove/replace, or a protected service unavailable through existing producer authority.

SEC-003, non_security_defect, unrelated_bug: F2. A caller supplies a mixed update -> core rejects an invalid entry but accepts another -> provider callback reports both -> a callback consumer may receive an inaccurate record -> no supplied code/configuration establishes that callback as a privileged authorization/persistence sink for a less-authorized principal. The caller already submits accepted updates and host code controls the callback. Saved consumer/result.json and the base comparison show the correctness delta; live source lines corroborate the callback logic. No fresh full StateProvider runtime test or deployment test is claimed. Confidence high in the saved correctness observation, with no demonstrated new security capability.

SEC-004, hardening, out_of_scope_hardening: JSON producer selects /elements/__proto__ in legacy React dispatch -> direct dictionary assignment bypasses the core path guard -> the local spec.elements prototype changes and can supply inherited element entries -> Object/Array/Function prototypes remain unchanged, and an ordinary own-element patch gives that producer the same element definition capability. This is a real broad rejection-contract limitation, not a confirmed global prototype-pollution vulnerability. The direct write is unchanged from base; a patch under this branch does not invoke changed core validation. No extra confidentiality, integrity or authorization capability was shown. Confidence high in the local behavior and modeled authority comparison. Follow-up may align renderer dispatch or own-key dictionaries, without being promoted to a security blocker. Arbitrary host code later treating inherited keys as privileged would require an evidenced sink, not an invented assumption.

SEC-005, hardening, out_of_scope_hardening: non-reserved property traversal uses `in` and ordinary reads; staged objects intentionally inherit source objects. A host that supplies custom inherited mutable objects, getters, proxies or explicit aliases to prototypes can expose them. JSON values cannot create those callable accessors or references by themselves. The authority to install such objects is not gained through this PR, and core guards still reject the named tokens. Own-property/type restrictions could reduce exposure but no new attacker capability is established here. No accessors/proxies or preexisting polluted runtime were actively exercised. Confidence medium for deployment-wide implications, high for the static implementation facts.
