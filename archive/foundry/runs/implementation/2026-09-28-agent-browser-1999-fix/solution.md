# Shaping synthesis and solution decision

Independent blind artifacts: shaping-sol.md (OpenAI GPT-5.6 Sol), shaping-kimi.md (Moonshot Kimi K3 Fast). Both received only frozen packet plus base interaction::fill, through independent FX invocations with no tools. The packaged worker's auth mode was unavailable because installed FX pins stored credentials; direct FX used the already-selected Keychain credential. Native subagents returned acknowledgements instead of performing the tasks. This is a recorded runtime-protocol deviation, not absent model-family independence.

Reconciled R are contract.md. Proposers' additions about global fill rewrites, all frameworks, iframe login discovery, aria-hidden semantics and rejecting hidden-first explicit CSS are derived suggestions, not settled requirements. Existing auth scans only main-document CSS; preserve that boundary.

Selected C2 (Sol C, scoped): preserve contributor's usable-element discovery and exact backend identity; add one auth-only renderer transaction. Resolve exact node, synchronously check attached/editable, focus, check exact active element, select, check again, execute native insertText/delete once, reject immediate detachment, inspect exceptionDetails, release object. No synthetic clear event and no page-level Input.insertText in auth. No new action retry. General fill is untouched.

Fit: R1 PASS original A/B + rerun owed; R2 PASS primitive probes + final action E2E owed; R3 PASS Chrome trusted input and actual React 19.2 probe (react-probe.json) + regression suite owed; R4 mechanism traced, pressure and cleanup tests owed; R5 packaging owed. Pass to implementation/detail for C2; publication remains gated by final evidence.

Observed probes: primitive-results.json and primitive-extended-results.json under Vercel evidence root. execCommand keeps trusted input and controlled-value tracking; native setter produces untrusted input. Detached/focus-removed/focus-redirected/select-removed/select-redirected targets reject before insertion. Normal email/text/password/search/url/tel/textarea and Unicode work; number sanitizes invalid text as a native number input. The first noninput probe was invalid and is excluded. No beforeinput event was emitted by execCommand in Chrome 152. React controlled submitted state exactly matched both inserted values.

Proposed chain: exact backend identity (inferred) -> attached/focus checks immediately before synchronous native edit (observed primitive) -> no task or CDP gap for queued rerenders (observed primitive) -> input callback can remove field after correct delivery (observed) -> reject connectedness failure before submit (implementation target). Deprecation/support failure must return error, never unsafe page-level fallback. Page-controlled monkeypatches are not a new attacker principal; the page already reads intended login values.

Failure catalog: S1 designed out by auth-only helper; S2 selection/focus/select/input variants; S3 username and password both covered; S4 active target plus connection, not backend resolution alone; S5 no persistent state; S6 no cross-process protocol; S7 errors propagate before submit; S8 cases derived from DOM lifecycle and callback boundaries; S9 source-PR red plus mutant tests; S10 real Chrome and React probes; S11 both credential consumers same helper; S12 native editing semantics measured, unsupported primitive rejects; S13 no session configuration changes. No accepted broadening.

Representation: compact operation sequence above, no new rendered diagram required. Detail: actions.rs auth helper + two auth call sites; preserve element.rs exact ref constructor and contributor selection/tests; e2e_tests.rs lifecycle regression.
