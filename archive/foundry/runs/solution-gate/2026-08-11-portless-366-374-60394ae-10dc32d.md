## 0. Trigger

Fires under two clauses. Both PRs are fixes for findings from earlier review rounds, and both alter contracts across parsers or processes where more than one solution shape is plausible.

## 1. Neutral contracts

### PR #366

**Violated property:** Framework flag injection must classify the framework's actual invocation grammar and place generated flags in the argument region owned by that framework, while preserving explicit user choices expressed through equivalent options.

**Observable that must change:**

1. `vite ./app` receives the assigned port and loopback host and listens on the assigned port.
2. In `npx -- vite dev`, the separator remains runner-owned and generated flags reach Vite.
3. Expo `--localhost`, `--lan`, and `--tunnel` receive the assigned port without a conflicting generated `--host`.

**Must not change:**

- Non-server commands such as `vite optimize`, `vite build`, `vp test`, `astro check`, and `expo export` receive no server flags.
- Flag values before subcommands are not mistaken for subcommands.
- Explicit port and host options suppress only their equivalent generated flag.
- Direct invocations, known package runners, and package-manager scripts continue to work.
- Unsafe scripts and option-terminated package scripts remain declined.
- Explicit server subcommands such as `vite dev ./app` continue receiving flags.
- Expo remains local by default outside Portless LAN mode, and LAN mode does not force Metro to loopback.

### PR #374

**Violated property:** Registration-time hosts resolution reporting and its internal trigger must decide from exact configured resolution and protocol semantics, remain bounded by the presence of a real producer, and compare the complete managed hosts-file mapping.

**Observable that must change:**

1. Existing Linux and Windows CLI tests remain below their five-second timeout when their mock proxy cannot acknowledge the trigger.
2. Custom `.local` outside active LAN mDNS still attempts resolution reporting and warns when unresolved.
3. `127.evil.test` proxies its POST to the app rather than invoking the internal trigger.
4. `127.0.0.1 active.test stale.test` is not an exact match for desired `active.test`.

**Must not change:**

- A current acknowledging daemon stays fast.
- A genuinely older daemon gets a bounded chance for its watcher to sync.
- A refused connection with no producer warns without paying the old-daemon ceiling.
- Resolvable `.localhost` names do not warn.
- Real LAN mDNS `.local` names are not required to resolve to loopback.
- The endpoint remains loopback-only and accepts no user hostname payload for writes.
- The same path under ordinary app hostnames continues reaching the app.
- Hosts exactness stays order-independent and rejects missing, extra, duplicate, and wrong-address mappings while ignoring entries outside the managed block.
- No new persistent handoff artifact is introduced.

## 2. Confirmed defects

All seven review findings reproduce at the reviewed heads.

### PR #366

1. `vite ./app` is classified as an unknown subcommand and receives no flags, although Vite declares `vite [root]` as its server grammar.
2. `npx -- vite dev` receives generated flags before the runner separator. npm interprets them as its own options and Vite never receives them.
3. Expo connection-mode flags receive an additional generated `--host localhost`. Expo exits because the connection modes are mutually exclusive.

### PR #374

1. Linux has one and Windows has six CLI tests reaching their five-second timeout. The local multi-TLD test takes about 5.27 seconds.
2. `reportHostsSync(["custom.local"])` returns before triggering or warning.
3. A POST for `127.evil.test` at the internal path returns 204 from Portless instead of reaching the registered backend.
4. A managed line with `active.test stale.test` is accepted as exact for desired `active.test`.

## 3. Forward chains

### Proposal A, PR #366: minimal parser additions

Main chain:

1. Add a Vite positional-root rule, separator-aware insertion, and Expo connection-mode aliases. **Proposed.**
2. Vite root invocations enter the server path, generated flags are inserted in the framework region, and Expo suppresses only generated host. **Inferred from the parser boundaries.**
3. The three reproduced inputs reach their intended framework argv without conflicting choices. **Inferred, mandatory implementation tests.**
4. Existing server and non-server classifications remain on the current paths. **Inferred.**

Harmful branch:

- Treating every unknown Vite positional as a root means `vite biuld` is accepted as a root. **Inferred.** This matches Vite's public `[root]` grammar, but makes typos fail later and with generated flags present.

Helpful branch:

- Host and port suppression stay independent, so Expo mode flags do not suppress the assigned port. **Inferred.**

### Proposal B, PR #366: parsed invocation with framework slice

Main chain:

1. Parse framework identity, framework-owned argv slice, server classification, and insertion index. **Proposed.**
2. Suppression reads only framework-owned arguments and generated flags are inserted at the framework option boundary. **Inferred.**
3. Runner-owned separators remain in place while direct, runner, and script paths use one classification result. **Inferred.**
4. New grammar cells become data rather than ad hoc scans of the full command. **Inferred benefit.**

Harmful branches:

- Each supported framework gains grammar metadata whose upstream drift can cause under-reach. **Inferred and admitted.**
- A separator can mean runner syntax or framework option termination depending on its position. A single global `indexOf("--")` repeats the current defect. **Observed mechanism, inferred design constraint.**

### Proposal A, PR #374: shorten the old-daemon fallback and harden matching

Main chain:

1. Reduce the fallback window when a responding peer does not acknowledge the new route. **Proposed.**
2. Synchronous CLI tests finish before five seconds even if their mock cannot answer. **Inferred by the proposal.**
3. Real older daemons receive less time for watcher and debounce work. **Inferred and admitted.**
4. Slow environments gain intermittent warnings or bind races. **Inferred harmful outcome.**

Matching branch:

1. Make `.local` exemption mode-aware, authority matching exact, and hosts parsing token-complete. **Proposed.**
2. The three matching defects close without a new state artifact. **Inferred.**

### Proposal B, PR #374: preserve producer states and tighten semantics

Main chain:

1. Keep `acted`, `mute`, and `absent` as distinct trigger outcomes. **Observed current contract.**
2. `acted` resolves immediately, `absent` checks once, and only `mute` pays the old-daemon fallback. **Observed current branch structure.**
3. A current daemon stays fast, no producer stays fast, and an old producer retains its bounded watcher opportunity. **Observed or directly implied by current branches.**
4. Tests must provide a producer capable of answering while the CLI executes synchronously. **Inferred.**
5. Moving mock proxies across a process boundary lets their event loop run during `spawnSync`. **Observed by the timing probe.**

Matching branch:

1. Pass effective LAN context into reporting, parse request authority, and parse complete hosts mappings. **Proposed.**
2. `.local` is exempt only for active LAN mDNS, app names beginning with `127.` remain routable, and extra aliases become visible. **Inferred.**
3. Separate peer-address and request-authority predicates avoid weakening the LAN security boundary. **Inferred.**

Harmful branches:

- More explicit context must be transported through all registration paths. Missing one call site recreates `.local` under-reach. **Inferred.**
- Authority parsing must reject alternate numeric spellings that URL parsers normalize to loopback. **Observed parser behavior, inferred security constraint.**

## 6. Synthesis

### PR #366

**Kind: graft, dominated by Proposal B.**

Chosen shape:

1. Introduce one parsed invocation result containing framework identity, the framework-owned argv slice or bounds, server classification, and the insertion point for generated options.
2. Model Vite's grammar explicitly:
   - no framework subcommand plus a first positional means default server with project root;
   - known server subcommands receive flags;
   - known non-server subcommands do not;
   - option arity prevents flag values from becoming subcommands.
3. Distinguish runner-owned `--` from framework option termination by position and parser state. Preserve runner separators before the framework executable and insert generated flags only inside framework argv.
4. For Expo, treat `--host`, `--localhost`, `--lan`, and `--tunnel` as host-mode choices. Any one suppresses only generated host. Generated port remains independent.
5. Reuse the same parsed result for direct invocations, package runners, and safe package-manager scripts. Preserve existing decline rules for compound, commented, env-prefixed, runner-flagged, and option-terminated scripts.

What came from Proposal A:

- Explicit independent suppression of Expo host and port.
- The admitted Vite typo tradeoff, which must be documented and covered.

Rejected material:

- Ad hoc additions to the current global scans. They repeat S2 and separator ambiguity.
- Any rule that suppresses Expo port together with host.

### PR #374

**Kind: graft, dominated by Proposal B.**

Chosen shape:

1. Preserve trigger states and production timing:
   - `acted`: check once immediately;
   - `absent`: check once and warn without the old-daemon ceiling;
   - `mute`: preserve the bounded fallback for an older producer.
2. Do not shorten the production fallback to satisfy CI. Move affected mock proxies into separate processes, or replace synchronous child execution with a harness whose producer event loop can run. Test the shipped fallback separately from the CLI integration timeout.
3. Pass explicit effective resolution context to reporting. A `.local` name is exempt only when it belongs to active LAN mDNS mode. A custom `.local` outside that mode is checked like any other loopback-managed name.
4. Split loopback predicates:
   - peer address may accept the IPv4 loopback range and IPv4-mapped loopback as required by the security boundary;
   - request authority accepts only canonical literal `127.0.0.1` or bracketed `::1`, with a valid optional port;
   - alternate numeric spellings, DNS names beginning with `127.`, and userinfo forms are not internal authority.
5. Parse every managed hosts line as address plus all hostname tokens before an inline `#` comment. Compare the complete multiset of `(address, hostname)` mappings against the desired set. Reject extras, duplicates, missing names, and wrong addresses while remaining order-independent and ignoring content outside the managed block.

What came from Proposal A:

- The concise separation of matching hardening into `.local`, authority, and token-complete hosts parsing.

Rejected material:

- Shortening the old-daemon window. The decisive probe located the failure in test orchestration, and shortening repeats S1, S4, S6, S7, and S9.
- DNS resolution of request authority.
- A new persistent producer marker.

   - accept `127.0.0.1`, `127.0.0.1:<valid>`, `[::1]`, `[::1]:<valid>`;

5. Hosts cells:
   - multiple aliases on one line;
   - inline comments;
   - duplicate aliases on one or multiple lines;
   - wrong address;
   - ordering differences;
   - unmanaged entries outside markers.
6. Mutation check: replacing exact authority with prefix matching, dropping later aliases, or skipping `.local` unconditionally must make a distinct test fail.
