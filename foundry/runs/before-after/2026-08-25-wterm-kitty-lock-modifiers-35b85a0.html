wterm PR #120 2026-08-25

Kitty lock modifiers keep legacy functional bytes

Caps Lock and Num Lock now preserve the same legacy F-key and DECCKM bytes as an unlocked keyboard, while Ctrl plus lock still uses the complete CSI modifier value.

Before

Locks forced CSI encoding

The former predicate treated lock bits as ordinary modifiers when selecting a legacy functional sequence.

Caps Lock + F1 CSI 1;65P
Num Lock + ArrowUp, DECCKM CSI 1;129A

After

Lock-only input stays legacy

The corrected predicate removes lock bits only for legacy eligibility and leaves full modifier serialization intact.

Caps Lock + F1 ESC OP
Num Lock + ArrowUp, DECCKM ESC OA

Limits

The exact-head Chromium suite passed 19 of 19 and the rebuilt artifact emitted the legacy bytes, but headless Chromium could not activate OS lock state. Active lock behavior is proven by direct getModifierState events, the fix-absent mutation, and the official Kitty reference oracle.
