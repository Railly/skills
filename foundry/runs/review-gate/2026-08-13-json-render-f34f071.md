## Findings fixed during the gate

1. `{ "$item": "/" }` initially resolved to an empty child segment. It now
   resolves to the enclosing repeat item, matching `{ "$item": "" }`.
2. Every renderer schema previously omitted `repeat`. The field is now present
   in all nine schemas, guarded by a parity test.
3. Structural validation initially duplicated issues for a reused DAG node.
   Deduplication now keys on element and structural repeat context while still
   validating inside-scope and outside-scope occurrences separately.
4. The cycle guard lacked a direct regression. A cyclic child-graph test now
   proves repeat validation terminates.

## Issue candidates

1. Normalize leading slashes in `$bindItem` paths. `resolveBindItemPath`
   currently joins `repeatBasePath + "/" + itemPath`, so `"/field"` produces a
   double slash while `$item` and the new repeat resolver accept either form.
   This behavior predates the fix and is outside PR #256's contract.
2. Align zero-item repeat output between runtime and static renderers. Runtime
   renderers retain an empty container while static renderers can remove the
   repeated element entirely. This is pre-existing general repeat behavior,
   not introduced by nested repeat paths.
