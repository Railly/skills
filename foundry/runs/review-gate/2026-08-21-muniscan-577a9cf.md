# Muniscan 100-site HTTP sample review gate

Status: pass

Exact head: `577a9cfb02b39a579dafe925bfa51d6e61ffe1b8`

The new command selects 100 municipalities from the published ranking, with
20 evenly spaced rows in each of five bands, then performs one sequential GET
per selected classified domain. It records status, final URL, elapsed time and
bounded errors, discards bodies and keeps the observations outside the score.

The independent oracle reconstructed all expected positions from the published
2026-08-08 snapshot without calling the production selector: 100 rows, zero
mismatches, 20 per band and 100 unique domains in this snapshot. Real Bun HTTP
producers exercised redirects, response metadata, connection failure and
sequentiality. Two fix-absent mutations failed at the intended assertions and
the restored focused suite passed 160/160 repeated tests.

The Radius map reports 351 unresolved calls against 149 edges, so it
under-covers and was used only for orientation. The same model family authored
and reviewed the change; the independent sampling oracle and real Bun HTTP
producer reduce, but do not erase, shared-prior risk.

The review does not claim that a live 100-domain observation already exists.
That remains the V8 post-merge publication gate.

## Exemptions claimed

- No score code changes are required because the new output is produced only
  after scoring and is never read by `score` or `diff`.
- No response-body schema is required because bodies are explicitly cancelled
  and never retained.
- A live external result is not required to merge the bounded collector, but
  V8 cannot be called complete until an actual 100-row artifact is reviewed.
