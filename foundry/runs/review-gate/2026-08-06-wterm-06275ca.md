## Findings

### P1 - mouse mode removes native text selection

`InputHandler.handleMouse()` always calls `preventDefault()` after emitting an SGR report (`packages/@wterm/dom/src/input.ts:284-316`). The feature is opt-in at the terminal protocol layer, but once enabled there is no user modifier that bypasses reporting and allows the browser to select DOM text. A review-only built-package drive dispatched a cancelable Shift+left `mousedown` while mode 1000/1006 was active: it emitted `ESC[<4;1;1M` and set `defaultPrevented`, rather than leaving the event to native selection. This regresses wterm's documented native-text-selection product contract. The current xterm reference path explicitly treats Shift as force-selection when mouse events are active.

### P1 - a mouse click reports focus after the press and release

Mouse tracking emits on `mousedown`, while WTerm focuses the hidden textarea only from its `click` listener (`packages/@wterm/dom/src/input.ts:134`; `packages/@wterm/dom/src/wterm.ts:69-73`). A built WTerm drive from a blurred mode-1000/1004/1006 terminal observed `press, release, focus` (`ESC[<0;1;1M`, `ESC[<0;1;1m`, `ESC[I`). The terminal application therefore receives the mouse gesture while it still believes the terminal is unfocused; a drag released outside may not produce `click` at all, so focus can remain absent. Focus the textarea during `mousedown` before delivering the mouse report. The reference terminal does this ordering explicitly.

### P1 - fixed-column terminals scale coordinates across unused CSS width

The coordinate formula divides the root content-box width by `getCols()` (`packages/@wterm/dom/src/input.ts:245-282`), even when the active grid occupies less width. This is reachable with `autoResize: false` or any host-controlled fixed-column core inside a wider element. In a built-package drive with 80 rendered columns spanning 800px inside a 1000px root, a click at x=395 (rendered column 40) emitted column 32. The padding and scrollback fixes are correct, but the remaining invariant is rendered cell geometry, not root geometry. Use measured cell width/row height or the active-row box, then clamp outside-grid capture coordinates.

### P2 - browser back/forward buttons are encoded as left clicks

The non-move button classifier maps middle and right explicitly and falls through every other `MouseEvent.button` value to code 0 (`packages/@wterm/dom/src/input.ts:299-312`). A review-only drive with browser Back (`button=3`, `buttons=8`) emitted `ESC[<0;1;1M`, armed capture, and prevented the browser action. Unsupported buttons must be rejected before capture/output, not reclassified as left.
