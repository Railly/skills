## Subsystem model and adjacent seams

GitHub owns issue and pull request truth. Durable calculations append compact inputs one provider page per request. Publication validates the full rank set and atomically advances the accepted report pointer only when generation and active calculation still match. Server rendering loads only page one for the active route, the filter cookie supplies first-render preference authority, and later rank pages merge into the client workspace. Reset increments generation, clears pointers, and deletes calculations and reports transactionally.

The adjacent seams checked were GitHub issue-versus-pull payload drift, stale calculations publishing after reset, a failed rerun replacing the latest good report, report and staging leaks after publication, malformed rank sets, unauthorized repository reads, selected items outside page one, and hydration reverting the Triage sort.
