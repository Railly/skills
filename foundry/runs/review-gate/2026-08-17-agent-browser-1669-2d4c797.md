## Outcome

The Vercel Agent Review finding was correct and is fixed.

The Linux-only launch block mixed `Option` and `Result`, treated `CaBundle` as optional after it had already been resolved, and returned `PreparedNssHome` where `Option<PreparedNssHome>` was required. macOS removed this block through `#[cfg(target_os = "linux")]` before type checking, so the host suite could not catch it.

The fix extracts `resolve_prepared_nss_home` as an all-platform helper with the explicit contract `Result<Option<PreparedNssHome>, String>`. Linux `try_launch_chrome` now consumes one resolved result without collapsing the two enums.

## Subsystem model

- `LaunchOptions` may carry a prepared NSS home, a parsed CA bundle, a certificate path, or no CA.
- `resolve_prepared_nss_home` applies that precedence on every platform, making the mixed enum contract type-checked on macOS and Linux.
- Linux `try_launch_chrome` attaches the resolved private NSS home to the Chrome process.
- The launch path propagates through `launch_chrome`, `browser::launch`, and the daemon's `auto_launch` and `handle_launch`.

The adjacent layers reviewed were input precedence, certificate read failures, NSS preparation failures, temporary-directory cleanup, prepared-home reuse, browser launch propagation, and OS-specific compilation.

## External finding

The bot reported that the Linux block did not compile. The repository CI reproduced four Rust type errors in `cli/src/native/cdp/chrome.rs`. The root cause was relying on a macOS-only verification run for code removed by `cfg(linux)`.

This class is now recorded in `cases/agent-browser/conventions.md`: code behind an operating-system cfg must compile on that operating system before push, with mixed resolution logic extracted into an all-platform helper when practical.
