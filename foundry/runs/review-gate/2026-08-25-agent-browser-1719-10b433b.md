## Blocking finding

### F1: A failed snapshot diff erases the last valid element refs

`handle_diff_snapshot` clears `state.ref_map` before `take_snapshot`. Selector resolution can fail after that clear. The command returns an error but leaves the session with no refs.

Real CLI reproduction at the exact head:

1. Snapshot a page where Chrome assigns `@e1` to a checkbox.
2. Run `diff snapshot --selector '[' --baseline ignored`.
3. The diff correctly reports an invalid selector.
4. `click @e1` now fails with `Unknown ref: e1` and the DOM checkbox remains unchecked.

The exact base commit preserves `@e1` under the same sequence, and the click checks the checkbox. This is introduced by the PR.

Fix direction: populate a fresh local `RefMap`, then replace `state.ref_map` only after `take_snapshot` succeeds. Apply the same transactional reasoning to both pages of `diff_url` and add a regression test for failure-state preservation.
