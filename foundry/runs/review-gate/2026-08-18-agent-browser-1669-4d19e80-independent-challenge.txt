Shared confirmed findings

2. A retained CA rejected provider, CDP, and auto-connect launches with an error that blamed `--ca-cert` even when the current invocation omitted it. The error did not tell the user to pass `--no-ca-cert`.
3. The helper-call-count test did not prove that each launch constructor carried the transition. Removing production wiring could leave the test green.
4. Successful iOS and Safari provider launches returned before persisting the resolved CA clear.
5. MCP and Eve silently preferred `caCert` when `clearCaCert` was also true, while CLI and daemon rejected the conflict.
