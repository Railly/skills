## Subsystem model

`WTerm.write()` sends each transport chunk through `WasmBridge.writeString/writeRaw()`. Zig's streaming parser retains fragmented CSI state, `Terminal.setPrivateMode()` toggles private mode 2026, `wasm_api.getSynchronizedOutput()` exports the final parser state, and `WTerm` decides whether to keep or cancel its `setTimeout(0) -> requestAnimationFrame -> Renderer.render()` chain. `Renderer.render()` consumes dirty rows and clears them. Side outputs (`getTitle()` and `getResponse()`) are also consumed inside `_doRender()`, so suppressing paint suppresses response delivery. `resize()` is a second render producer: it mutates the core, immediately rebuilds the renderer rows, and schedules a frame without consulting mode 2026. `destroy()` owns cancellation of both timer stages.

There is one browser process and one WASM instance; no detached process or alternate output channel exists. Consumers of the new rule are `WTerm.write()` and the public `TerminalCore` implementations. `WasmBridge` exposes the rule; `GhosttyCore` does not implement the optional method and therefore retains ordinary per-write rendering.

Adjacent layers carried into the lenses were: response delivery while paint is held, resize as an independent paint producer, missing-close recovery/timeout, timer-to-RAF cancellation, close/reopen chunk boundaries, public API documentation, alternative-core compatibility, and regression tests that must fail when DOM suppression is removed.

## Findings

### High — host responses deadlock behind the synchronized paint hold

`WTerm.write()` cancels rendering whenever mode 2026 is active (`packages/@wterm/dom/src/wterm.ts:153`), but the only call to `getResponse()` remains inside `_doRender()` (`packages/@wterm/dom/src/wterm.ts:238`). Driving the built package with the committed WASM using `CSI ? 2026 h`, then `CSI 6 n`, produced no `onData` callback while the mode was open; the queued CPR `ESC[1;1R` appeared only after `CSI ? 2026 l`. A host that asks for cursor state and waits for the reply before closing synchronized output deadlocks indefinitely. Response draining must be independent of paint scheduling.

### High — an unterminated synchronized block blanks all later output indefinitely

There is no maximum hold duration or recovery timer. Driving `CSI ? 2026 h` plus `NEVER-CLOSED` against the built DOM/WASM artifact left the DOM empty and `synchronizedOutput() === true` after 5.2 seconds; an additional write still did not paint. A truncated stream, crashed producer, or malicious remote can freeze the terminal for the rest of the session. Add a bounded fallback that flushes and releases the hold, with cancellation/re-arming tests.

### Medium — resize bypasses mode 2026 and paints a partial frame

`resize()` always calls `renderer.setup()` and `_scheduleRender()` (`packages/@wterm/dom/src/wterm.ts:160-168`) without checking the synchronized-output state. End-to-end drive: after `CSI ? 2026 h` plus `PARTIAL`, the DOM correctly stayed blank; calling `term.resize(80, 24)` exposed `PARTIAL` before `CSI ? 2026 l`. Auto-resize can therefore violate the atomic paint contract. Resize must preserve the last committed frame or keep its render held until close/recovery.

### Medium — the DOM regression has no test with teeth

The PR adds parser/WASM getter tests only. In a scratch copy of HEAD, replacing `packages/@wterm/dom/src/wterm.ts` with the `origin/main` implementation while retaining every PR test left the focused core suite at 32/32 and DOM suite at 33/33. Thus the user-facing fix can be fully reverted while all tests in this PR remain green. The historical evidence branch contains an appropriate DOM contract, but it is absent from PR #106. Add tests for open/write/no-paint, close/one-paint, timer and RAF cancellation, resize while held, response delivery while held, destroy, and timeout recovery; force-red each behavior at its own layer.

### Medium — the new public core API is absent from package and web documentation

`TerminalCore.synchronizedOutput?()` and `WasmBridge.synchronizedOutput()` are exported public methods, but `packages/@wterm/core/README.md`'s method table and `apps/docs/src/app/core/page.mdx` / API reference contain no `synchronizedOutput` or mode-2026 entry. This is a user-facing API change under `AGENTS.md`'s documentation rule. The deterministic surface gate passed because its wildcard surface rule did not flag these concrete files; reading the required surfaces at the claim layer confirms the omission.
