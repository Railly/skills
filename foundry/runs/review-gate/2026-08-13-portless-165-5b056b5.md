## Findings

### High: wildcard routing chooses path specificity before hostname specificity

`findRoute()` gathers every wildcard hostname suffix and then sorts the combined set only by path-prefix length. With root route `api.acme.localhost` and `/api` route `acme.localhost`, a request to `admin.api.acme.localhost/api` selects the broader `acme.localhost/api` route instead of the more specific hostname.

Reproduced against the built proxy:

```text
Host: admin.api.acme.localhost, GET /          -> API
Host: admin.api.acme.localhost, GET /api       -> ROOT
Host: admin.api.acme.localhost, GET /api/users -> ROOT
```

Resolve hostname specificity first, then apply longest path-prefix selection within that hostname tier. See `packages/portless/src/proxy.ts:155-156`.

### Medium: accepted dot segments create routes that no request can reach

`normalizePathPrefix()` accepts standalone `.` segments and stores them literally, while the WHATWG URL parser canonicalizes them before matching:

```text
normalizePathPrefix("/api/.") -> "/api/."
new URL("/api/.", base).pathname -> "/api/"
```

Dogfood registered `dotdemo.localhost/api/.`, but `/api/.`, `/api/`, and `/api/x` all returned 404. Reject standalone `.` segments or canonicalize with the same URL semantics used for requests before storing route identity. See `packages/portless/src/utils.ts:144-160`.

### Medium: explicit `--path /` cannot override environment or config

The root flag normalizes to `undefined`, then the falsy fallback reloads `PORTLESS_PATH` or the config value. This violates the stated `flag > env > config` precedence.

Reproduced:

```text
PORTLESS_PATH=/api portless precedence --path / ...
-> http://precedence.localhost:18165/api
```

The parser needs to preserve whether the flag was explicitly supplied separately from its normalized root value. See `packages/portless/src/cli.ts:1685-1709`, `packages/portless/src/cli.ts:1736-1792`, and the config fallback at `packages/portless/src/cli.ts:4170-4171`.

### Low: the documented path configuration contract disagrees with the CLI

The new surface is incomplete in several contract-carrying passages:

- `PORTLESS_PATH` is advertised generally, but multi-app mode explicitly ignores it at `packages/portless/src/cli.ts:3861-3864`.
- Configuration precedence documents `name`, `script`, and `appPort`, but omits `path`.
- The web configuration page and agent skill still say package.json objects support only `name`, `script`, `appPort`, and `proxy`, despite code accepting `path`.
- `portless alias --help` omits `--path` even though alias registration and removal accept it.

Update each canonical passage and state the multi-app exception explicitly. See `apps/docs/src/app/configuration/page.mdx:99`, `apps/docs/src/app/configuration/page.mdx:151-159`, `skills/portless/SKILL.md:364`, and `packages/portless/src/cli.ts:2331-2344`.
