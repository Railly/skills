## Subsystem model

- `WTerm` owns the terminal scroll state and classifies each scroll event as programmatic or user-owned.
- The virtualized renderer can change `scrollHeight` while output is streaming.
- Chromium may clamp `scrollTop` synchronously during the DOM mutation and deliver the corresponding event later.
- Input returns the terminal to the bottom. Resize preserves either bottom-follow state or the first pending history offset.
- A DOM-owned reclamp that lands at the current bottom preserves follow state. A movement outside the bottom threshold and accepted-position tolerance transfers ownership to the user.

## Findings resolved

1. Reusing one Electron process across geometry cases contaminated later fixtures. Each geometry and history case now runs in its own Electron process.
2. The original accepted-position token did not cover a renderer-induced geometry shrink. Chromium reclamped `154.4` to the new bottom `0`, and the late event cleared follow state. Current-bottom attribution closes this path.
3. The first harness attempts could exit green before artifact and exit-code propagation. The final harness ignores `window-all-closed`, requires JSON artifacts, and calls `app.exit(code)`.
