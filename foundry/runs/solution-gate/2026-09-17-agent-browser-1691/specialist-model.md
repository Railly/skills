# Behavioral model and evidence scope

Independent oracle: saved Browser Use Cloud V4 OpenAPI (original review directory, browser-use-v4-openapi.json), the reconciled ownership contract, Rust cancellation semantics, and a real Chrome CDP producer. Loopback fixtures serve real HTTP bytes matching the API schema; they do not establish hosted producer behavior.

| Dimension | Values / equivalence partitions | Expected observable | Falsifier / limit |
|---|---|---|---|
| Prior ownership | absent, pending, attached | pending ID blocks replacement; ordinary commands preserve attachment | same-ID retry/launch tests; canceled-stop ownership mutation |
| Create transport | full response, refusal, stalled body, unknown outcome | one request; bounded categorized error; no automatic replay | timeout mutation and built stalled CONNECT proof |
| Create identity | valid UUID, absent, malformed/path-like, reflected UUID credential | ownership only for safe validated resource ID; no credential echo | HTTP matrix; reflection test; per-cell parser mutations not all run |
| CDP value | ws, http, absent/null, malformed | attach supported values; roll back after known allocation for missing endpoint | protocol matrix, null-CDP rollback, HTTP acceptance, real Chrome discovery; hosted producer unavailable |
| Receipt storage | writable, unwritable existing dir, delayed write | preflight rejection before POST; ID retained before awaited write | blocked filesystem worker and omitted-callback mutation; filesystem syscall failure after successful preflight is not directly forced |
| Stop response | matching stopped ID, different ID, active status, bad JSON, 404, 500, transport cancellation | clear ownership only on positive matching stop acknowledgment | stop-status mutation; acknowledgment matrix; real CONNECT cancellation |
| Setup caller | explicit, automatic, implicit replacement | bounded setup, preserve config on error; no overwrite of pending remote ID | explicit filter mutation, automatic configuration mutation, pending-owner launch test |
| Cleanup cancellation | while network stop pending | retained ID with cleared local launch bookkeeping | close take() and bookkeeping mutations through close_current_browser |
| Workflow continuity | local Chrome, external Chrome, owned-provider-shaped attachment | stable target, URL and DOM sentinel; external Chrome survives detach | real Chrome e2e and built CLI continuity; remote Cloud route not exercised |

Exclusions: provider-specific live billing/profile/recording/repeated-stop semantics require an actual Browser Use Cloud account. Forced process death before a complete ID response cannot provide ownership and is explicitly an unknown outcome. Receipts are manual recovery hints, not fsync-backed restart state. No automatic create retry or persisted retry queue is introduced.

Test Strength executes seven reversible faults in production implementations/callers. Each narrow test must fail its behavior assertion (compilation failure is invalid), sources are restored in finally, and the entire Browser Use group runs green afterward. No surviving mutation is accepted silently. The campaign is deterministic (loopback ports assigned by OS; bounded waits). It is not exhaustive property-based generation or bounded structured fuzzing; these omitted campaigns and missing per-cell parser/caller faults remain explicit verification gaps, so the full Test Strength receipt is incomplete.

Resilience commit points: (C1) provider may allocate before client observes a response, owned externally until parsed ID; (C2) parsed ID synchronously handed to daemon, then local receipt write and CDP attach may fail; (C3) attached manager published to daemon, then network setup/state load may fail; (C4) remote stop acknowledged, then local receipt deletion may fail. Known-ID failures preserve the retry owner; unknown outcomes return fixed inspect-Cloud guidance. Stop requests are 4s bounded; create/read 10s, attach 8s, encompassing setup 18s, timeout cleanup 4s.

Forced partitions: C1 stalled CONNECT/body and malformed/error response; C2 unwritable preflight, blocked post-ID receipt task, missing/null endpoint rollback success/failure, refused CDP attach; C3 local/external continuity and explicit/automatic failed setup configuration rollback, but no live provider post-attach state-load failure; C4 positive loopback acknowledgment and receipt deletion polling, but permission-denied deletion and hosted repeated stop are not forced. Immediate same-ID caller retries are exercised with missing-key rejection; a positive stop through the complete CLI wire is not exercised. Cancellation uses real pending CONNECT and blocked filesystem threads. Final binary adds concurrent close and idle-shutdown pressure.

Security scope: fixed HTTPS API destination with default certificate verification and redirects disabled; API key appears only in header; receipts and lifecycle diagnostics exclude the key, endpoint and hostile response body. The Cloud provider and local operator already have authority to see the key. A remote web page or unauthenticated network peer does not gain a new credential sink. Receipt UUIDs are resource identifiers, not authentication secrets; no cross-user ACL confidentiality or power-loss durability claim is made. UUID-shaped credential reflection is rejected before receipt writing or ID diagnostics. Security review is limited to these changed boundaries, not a penetration test of Browser Use Cloud.
