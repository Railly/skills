## Neutral contract

Property violated: Application-supplied OSC 8 hyperlink identity does not survive the terminal-core boundary to the rendered cell range.

Observable that must change: After writing an OSC 8 open sequence, linked text, and an OSC 8 close sequence, exactly the covered terminal cells in the active viewport and after entering scrollback expose the emitted URI and render as a safe clickable link, with no URI on neighboring cells. This must hold for both the built-in core and `GhosttyCore`, including BEL and ST termination and optional `id=` parameters.

Must not change:

- Ordinary output remains non-clickable by default.
- Regex URL detection remains a separate opt-in feature.
- Existing `TerminalCore` implementations remain source-compatible.
- SGR styling, grapheme strings, wide/continuation cells, block glyphs, cursor placement, dirty rows, scrollback virtualization, selection, resize/reflow, alternate-screen isolation, erase, overwrite, and rollover retain their behavior.
- Hyperlink coverage follows cell mutation semantics.
- Unsafe or executable URI schemes never become navigable DOM.
- No version or changelog work enters the feature PR.

The proposals are preserved in [2026-08-12-wterm-osc8-proposals.md](2026-08-12-wterm-osc8-proposals.md).

## Observed baseline

The current built-in parser recognizes BEL and ST as OSC terminators, but `Terminal.handleOsc` handles only OSC 0 and 2. Its cell is a 12-byte extern struct with two padding bytes.

Ghostty 1.3.1 already parses OSC 8, tracks an explicit or implicit identity, stores hyperlink membership outside the cell in page-local maps, preserves it through page operations and reflow, and clears it on overwrite. Wterm's Ghostty adapter exports only glyph, style, color, grapheme, and width data. Bytes 14–15 of its 16-byte packed cell are reserved.

Executed baseline:

```text
{"kind":"builtin","activeText":["LINK plain","ST tail"],"activeFields":[["bg","char","fg","flags","width"],...]}
{"kind":"builtin","scrollbackCount":7,"oldestText":"LINK plain",...}
{"kind":"builtin","domText":"LINK plain","anchors":0,"htmlHasUri":false}
{"kind":"ghostty","activeText":["LINK plain","ST tail"],"activeFields":[["bg","char","fg","flags","width"],...]}
{"kind":"ghostty","scrollbackCount":7,"oldestText":"LINK plain",...}
{"kind":"ghostty","domText":"LINK plain","anchors":0,"htmlHasUri":false}
```

Both cores consume BEL- and ST-terminated sequences as control data and preserve display text. Neither exposes URI metadata to JavaScript, and the DOM emits zero anchors.

## Forward chain: Fable

Main branch:

1. Per-cell built-in table index occupies existing padding; Ghostty exports its native hyperlink metadata. **Mechanism:** existing grid, scrollback, resize, and page operations move complete cells or native page metadata. **Observed** for layouts and copy paths.
2. Hyperlink coverage moves with the same storage as glyph width and style. **Mechanism:** no parallel range structure must mirror mutation methods. **Inferred** from the copy paths.
3. Optional resolved metadata reaches `CellData` for active and scrollback reads. **Mechanism:** both renderer paths already consume `CellData`. **Observed**.
4. Renderer breaks runs on hyperlink identity and wraps only allowed URIs. **Mechanism:** the current row builder already breaks on style, cursor, wide, and block boundaries. **Inferred**.
5. Exact cell coverage becomes clickable without detecting URLs from reconstructed text. **Mechanism:** the core, not a regex, owns cell identity. **Inferred**, verification target.

Harmful branches:

- The built-in URI arena fills. New OSC 8 links fail closed to plain text. **Guessed** until capacity is selected and saturated.
- A payload exceeds `MAX_OSC`. Without a truncation bit, a truncated URI could be accepted. **Observed** parser behavior, and the original proposal's "no parser state changes" claim was refuted.
- Link-heavy Ghostty rows cause repeated WASM URI lookups. **Inferred** unless row-level caching and interning bound calls.
- Anchor nesting changes consumer DOM assumptions and browser selection details. **Inferred**.

Helpful branch:

- Existing cell movement paths become regression coverage for hyperlinks rather than new feature-specific movement code. **Inferred**.

## Forward chain: Gemini

Main branch:

1. Each packed cell exposes a numeric link ID. **Mechanism:** renderer asks a required `TerminalCore.getLinkUri(id)` resolver. **Proposed**.
2. Renderer caches resolved IDs and groups contiguous equal IDs. **Mechanism:** equality is delegated to a global numeric namespace. **Guessed**.
3. URI strings cross WASM only on cache misses. **Mechanism:** ID-to-string resolution is lazy. **Inferred**.
4. DOM anchors cover linked cells. **Mechanism:** numeric equality defines link runs. **Inferred**.

Harmful branches:

- Ghostty IDs are page-local and are remapped when data moves between pages. A global resolver can return the wrong URI or no URI. **Observed**.
- Making `getLinkUri` required breaks structural third-party implementations. **Observed** by TypeScript compilation.
- Grouping by explicit OSC `id=` alone does not represent implicit links, which Ghostty assigns unique screen-level identities. **Observed** in Ghostty source.
- The two proposed predictions omit active/scrollback parity, BEL/ST, third-party compilation, and current rendering regressions required by the brief. **Observed**.

## Synthesis

Kind: **graft**.

Take from Fable:

- Metadata is attached to cell semantics inside each core.
- Built-in core uses the existing two padding bytes as a bounded table index, keeping its 12-byte stride.
- Ghostty keeps its native storage and exports resolved metadata through both active and scrollback paths.
- Public `CellData` additions remain optional.
- Renderer owns URI policy and safe anchor creation.

Take from Gemini:

- The renderer needs an identity key separate from display styling and URI text to preserve logical grouping.

Correct both with probe evidence:

- Do not expose Ghostty's page-local numeric ID as the public identity.
- Expose optional flat fields: `linkUri?: string`, `linkId?: string` for the explicit OSC parameter, and `linkKey?: string` as an opaque core-produced semantic key.
- For the built-in core, an implicit OSC 8 open gets a fresh identity. Explicit links may share identity only when URI and explicit `id=` match.
- For Ghostty, derive `linkKey` from its page entry's explicit ID or stable implicit identity after resolving through the owning page.
- Add `osc_truncated` state to the built-in parser. Any truncated OSC 8 sequence is ignored as a link.

The seam is the resolved per-cell contract: adapters translate their private indexes into `linkUri`, `linkId`, and `linkKey`; the renderer never resolves a private ID.

## Chosen shape

1. Built-in parser recognizes `OSC 8 ; params ; URI` on BEL and ST, parses only `id=`, treats empty URI as close, and fails closed on truncation.
2. Built-in terminal owns a bounded URI/identity arena. Cells store a u16 entry index in existing padding. Blank, erase, and overwrite cells carry zero. Whole-cell copies preserve membership.
3. Ghostty's WASM adapter marks linked cells in its reserved packed layout and provides active and scrollback hyperlink readback that resolves the owning page entry.
4. Both JS cores intern decoded metadata and return optional `linkUri`, `linkId`, and opaque `linkKey`.
5. The DOM renderer treats `linkKey` as a run boundary, preserves style/wide/block/cursor behavior within the anchor, uses native anchors with `rel="noopener noreferrer"`, and emits no anchor for disallowed or invalid schemes.
6. Tests drive both cores through active viewport, scrollback, overwrite, erase, resize/reflow, alternate screen, wide/grapheme cells, rollover, BEL/ST, explicit/implicit identity, unsafe URI, and third-party compatibility.

## Carried assumptions for implementation

- A bounded built-in arena can cover practical workloads without unbounded allocation. Saturation must be explicitly tested and fail closed.
- Ghostty's public Zig module surface permits resolving active `RenderState` row pins and scrollback page pins in the adapter. Compile this as the first implementation spike.
- An opaque string `linkKey` is sufficient for renderer grouping without exposing private numeric indexes.
- Scheme policy is a product decision. Default recommendation: `http:` and `https:` only for the first PR unless existing project policy says otherwise.
- Anchor construction through the current string renderer can remain safe if both URI policy and attribute escaping are tested. If the escape proof fails, switch only anchor construction to DOM APIs.
