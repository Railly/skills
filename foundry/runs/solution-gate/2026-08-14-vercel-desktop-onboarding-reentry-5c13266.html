Proposal A: re-entry reconciler

observed existing fields describe picker, agents, and draft

inferred one incomplete-onboarding opener → preserve valid progress or repair absent state

inferred current-scope check → no stale-team draft

Proposal B: explicit step machine

inferred named onboarding step → view no longer infers by absence

guessed future steps become easier to add

inferred new step plus old phase, agent flag, and draft phase → overlapping truth unless broadly refactored

Harmful branch: larger S1 surface across working sign-in and Settings paths.

Chosen graft

  1. Use one runtime-only reconciler for authenticated incomplete onboarding.
  2. Keep the existing picker state and preserve agent selection across window close.
  3. Preserve an edited draft only when its scope still matches the selected account.
  4. Initialize absent or stale drafts with the existing default-draft transition.
  5. Keep true signed-out reset separate.
  6. Render create-key only when a form exists. Never initialize from the view.
  7. Do not add persistence or relax button validation.
