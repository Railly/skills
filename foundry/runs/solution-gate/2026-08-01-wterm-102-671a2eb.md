# Solution gate: wide-character width model (PR #102 review findings)

Date: 2026-08-01. Target `671a2eb` on `fix/wide-unicode-cells`.
Proposers: `fable-5` (A), `gpt-5.6-sol` @ high (B), isolated clones under `~/Programming/vercel/_sg102/{p1,p2}`.
Synthesis: `claude-opus-5`. Input: the five confirmed findings from the review gate at `2026-08-01-wterm-671a2eb.json`.

## Step 0 — Trigger

Fires, in the highest-risk class: this is the fix for a previous review round, so S1 and S2 carry extra weight. Also multiple shapes and a contract between components.

## Step 1 — Defect as contract

**Property violated.** `CellData.width` was added so a wide glyph owns two columns. The grid operations were written when one cell meant one column and were updated one at a time, with no stated invariant. Nothing says what must be true of a row once widths exist, so every operation decides for itself.

Whether that is one defect or five was left to the proposers.

## Step 2 — Proposals

Both rejected five local patches, both put a row invariant in `grid.zig`, both moved repair to choke points, both had DCH/ICH shift exactly n and repair the seams, both replaced the hand-written classifier with a generated table, and both kept zero-width out of scope.

They diverged on four things:

| | A | B |
|---|---|---|
| Framing | one defect, five symptoms | 1/2/4 structural; 3 and 5 separate boundary defects |
| DECAWM off at margin | rewind, place in the last two columns, "which is xterm's behavior" | reject the glyph, do not store it |
| Spacer head | renderer emits a blank for a stray continuation; do not touch the ghostty wasm | adapter maps `.spacer_head` to a width-1 blank |
| Unicode table | generate from EastAsianWidth W/F | generate from W/F **intersected with assigned scalars**, because raw ranges "include unassigned U+3040" |

## Step 3 — Probe log

**P1 — the duplicate-logic claim (A).** Confirmed, and it corrected my own earlier read. Four implementations of the pairing rule: `clearRangeAs` (`grid.zig:61`), `clearWideCellAt`, `expandWideRange`, `sanitizeWideRow` (`terminal.zig:111/136/153`). My first grep was scoped to `terminal.zig` and found three.

**P2 — the shipped test encodes the defect (A).** Confirmed.
```zig
test "delete chars keeps wide cells intact" {
    t.write("📁ab");  t.write("\x1b[1;1H\x1b[P");
    try testing.expectEqual(@as(u32, 'a'), t.grid.getCell(0, 0).char);  // shift of two for DCH 1
```
Fixing finding 4 requires rewriting this test. Both proposals accept that; it is a reviewer-visible admission.

**P3 — the resize ordering (found in groundwork, independently reached by A).** `resize` truncates columns for `preserve_rows`, pushes rows to scrollback, and only then runs `sanitizeWideRow` over `0..rows`, the new grid. Rows leaving to scrollback never pass the sanitizer. That ordering is the whole of finding 1. The invariant already exists in code; there is no single funnel applying it.

**P4 — B's Unicode claim. REFUTED.** Fetched `https://www.unicode.org/Public/UNIDATA/EastAsianWidth.txt`.
- No W/F range contains U+3040. The `@missing` default is `N`.
- The header's default-W blocks are `U+3400..U+4DBF`, `U+4E00..U+9FFF`, `U+F900..U+FAFF`, plane 2 and plane 3 only. Hiragana is not among them.

So plain generation from W/F plus the documented default-W blocks already yields U+3040 → narrow. B's intersection is unnecessary, and it is **actively harmful**: unassigned code points inside `U+4E00..U+9FFF` are legitimately W, and intersecting with assigned scalars would make them narrow. B's rejected-alternative reasoning is inverted.

**P5 — A's xterm claim. UNVERIFIED.** A asserts that placing the glyph in the last two columns with DECAWM off "is xterm's behavior". No xterm here. The only reference implementation I can measure, ghostty, **drops** the glyph: `ESC[?7l` + `abcd界` in five columns leaves `20:1` at column 4. Searched ghostty's own `Terminal.zig` tests for a DECAWM-off wide-at-margin case and found none; its margin tests all run with wraparound enabled. Recorded as an unverified assumption, not upgraded to a fact and not refuted either.

## Step 5 — Synthesis: graft

**Take B's framing.** Findings 1, 2 and 4 are one structural defect; 3 (classifier) and 5 (ghostty adapter) are separate boundary defects that happen to share a symptom. A's "one defect, five symptoms" overstates: the classifier and the adapter do not share a cause with the grid operations.

**Take the shared structure**, which both reached independently. The invariant lives in `grid.zig`: a row is tileable by width-1 cells and adjacent `[2,0]` pairs; a width-2 cell may not occupy the final column; width 0 may only follow width 2. `Grid` owns width-aware mutation; `Terminal` supplies policy and stops repairing cells itself. Operations do their literal work and repair the seams.

**Take A's precision on the scrollback site.** Repair at the `scrollback.push` call site, not just before the resize push, because that also covers the linefeed-scroll push at `terminal.zig:423`. Enforce on write; history stays immutable and trustworthy.

**Take A's classifier**, plain generation from EastAsianWidth W/F plus the documented default-W blocks, with the Unicode version pinned and the generator checked in. Reject B's intersection, refuted by P4.

**Take B's spacer-head fix** (adapter maps `.spacer_head` to a width-1 blank) **and add A's renderer rule** as defense in depth. B is semantically right: `width === 0` means continuation, full stop, and an adapter that exports a spacer head as 0 is lying. A's objection was the ghostty wasm rebuild, which is cheap now that `rebuild-wasm:docker` exists on this branch's parent. A's renderer rule stays because it protects against an orphan from any core, including the built-in one during a future regression.

**Leave DECAWM-off open.** A places the glyph in the last two columns, B rejects it. A's justification is the unverified xterm claim; B's matches the only implementation measured. This is the one decision the gate did not resolve, and it should not be resolved by argument.

## Carried assumptions

1. xterm's DECAWM-off behavior at the right margin with a wide glyph. Unverified. **Probe before implementing finding 2**: install or find xterm, or read `ctlseqs`/the VT510 spec on DECAWM with double-width. Until then the shape for finding 2 is undecided.
2. That removing `expandWideRange` from DCH does not break the two passing wide tests other than the one being rewritten.
3. That the generated table's size increase (~1-2 KB of wasm) is acceptable.

## Must-not-change list → Review Gate

- Valid wide pairs render once, survive scroll into scrollback, and survive resize when both columns fit.
- `CellData.width` semantics as shipped: 1 narrow, 2 wide leading, 0 continuation.
- The renderer's wide-cursor handling fixed in `671a2eb`.
- `wterm.wasm` in sync with `src/*.zig`; CI rebuilds and diffs it.
- 29/29 turbo tasks.

## Post-synthesis verification pass

Hunter asked for everything verifiable to be verified before implementing. This closes the one deferred decision and pins the expected values.

**The DECAWM-off decision is resolved: reject the glyph. A's premise is refuted.**

A claimed placing the glyph in the last two columns "is xterm's behavior". Read xterm's own `dotext` in `charproc.c` (ThomasDickey/xterm-snapshots, lines 6990-7175). With `WRAPAROUND` clear it does this:
```c
width_here -= last_chomp;
if (chars_chomped > 0) {
    if (!(xw->flags & WRAPAROUND)) {
        buf[chars_chomped + offset - 1] = buf[len - 1];   // substitute in place
    } else { need_wrap = True; }
}
```
Substitution into the last fitting position, not a rewind. Grepped the whole path for a column rewind (`cur_col -=`, `cur_col - 2`, `CursorBack`): none. Whatever xterm does there, it is not what A described.

Two independent implementations drop instead. Alacritty is explicit:
```rust
} else {
    // Prevent out of bounds crash when linewrapping is disabled.
    self.grid.cursor.input_needs_wrap = true;
    return;
}
```
and ghostty drops, measured: `ESC[?7l` + `abcd界` in five columns leaves `20:1` at column 4.

So B's shape for finding 2 stands on two verified implementations and A's stands on a refuted reading. Take B.

**Expected values for the rewritten tests, measured rather than derived.**

| case | built-in today | ghostty | take |
|---|---|---|---|
| DCH at the wide **lead**, `📁ab` + `CSI 1;1H CSI P` | `a b _ _ _` (shift 2) | `_ a b _ _` (shift 1, blank at front) | ghostty |
| ICH at the **continuation**, `A界BC` + `CSI 1;3H CSI @` | `A _ 界 cont B C` (rewound to lead, pair kept) | `A _ _ _ B C` (insert 1, pair destroyed, shift 1) | ghostty |

Ghostty's results are the "shift exactly n, repair the seams" behavior both proposals converged on. B predicted the ICH row exactly (`41:1 20:1 20:1 20:1 42:1`) without measuring it.

**Which shipped tests break: exactly one.**
- `delete chars keeps wide cells intact` asserts the shift-by-two and must be rewritten to `_ a b`.
- `wide characters advance by two cells` and `insert blanks shifts wide cells without splitting them` both place the cursor on the wide **lead**, never on a continuation, so the change does not touch them. Verified by reading each.

**Still unverified, low stakes.** The generated table's contribution to wasm size (estimated 1-2 KB). Measurable only after generating it.
