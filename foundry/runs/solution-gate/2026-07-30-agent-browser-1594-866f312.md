# Solution gate: agent-browser #1594, four defects at head 866f312

Runtimes: proposers `fable-5` (Agent, high effort) and `openai/gpt-5.6-sol` (codex exec, high effort),
blind to each other, each in its own detached worktree at 866f312. Synthesizer and implementer:
`claude-opus-5`, which proposed nothing. Brief at `/tmp/rg1594/brief.md`, written with the violated
property, the observable, and the must-not-change list, and with every candidate shape stripped.

## 0. Trigger

Fires. D1 and D2 are fixes for findings from a previous review round (maintainer `ctate`), which
takes the gate regardless of size. D3 and D4 change contracts (a CDP payload shape, a channel
payload type).

## 1. Defects as contracts

| | Violated property | Observable that must change |
|---|---|---|
| D1 | A per-connection rate limiter initializes its clock from a timestamp that does not correspond to a delivery. | Interval between the first and second delivered frames equals the configured interval, seeded and unseeded; an undelivered connection is never postponed by the cap. |
| D2 | A teardown operation reports completion while a task it owns can still run and act on shared state. | After teardown returns, no per-connection task can dispatch to the browser or mutate the process-wide activity clock, including when the writer is blocked mid-send. |
| D3 | An optional field absent from a client message is forwarded downstream as explicit null; the protocol rejects the whole request and the rejection is discarded. | Key press and release, printable and non-printable, in the shapes this repo's docs and dashboard emit, produce page events. |
| D4 | A value known at construction is recovered by reparsing the entire serialized message on every delivery. | No full-message parse on the delivery path. |

Must-not-change, per defect, is in the brief and is handed to Review Gate step 5.

## 2. Proposals

Both returned verbatim in the run log of the parent session. The notable result is **convergence on
all four shapes** between two different families that could not see each other:

- **D1**: `last_sent: Option<Instant>`, `None` until a real delivery, set only after a successful
  send (seed included); `deadline_from(None)` yields "immediately"; after a seed send, derive
  `next_allowed` from it so a URL-declared cap governs the seed-to-second gap.
- **D2**: `accept_loop` owns connection tasks in a `JoinSet` and drains it before returning, so
  awaiting `accept_task` transitively covers every connection; the reader is owned by its connection
  rather than detached. Both chose **abort over await**, because a client that is not reading can
  block a graceful drain forever.
- **D3**: build the keyboard params as a map and insert `key`/`code`/`text` only when the client sent
  a string. Both **rejected empty-string defaults** on semantics.
- **D4**: carry the id beside the payload in the watch channel (`{seq, json}`), assigned once at
  construction; parse once at the legacy `broadcast_frame` boundary to preserve its current
  behavior, including "no id means the writer never holds".

Divergence was confined to D2's mechanism detail: `fable` proposed an abort-on-drop guard around the
reader handle; `codex` proposed running the writer as a separately cancellable future so dropping it
cancels a blocked send, then aborting and awaiting the reader.

## 4. Scoring against the recorded failure shapes

Weighted S1 and S2 highest, since D1 and D2 are fixes for a previous round.

- **S1 over-reach.** D1 hit, accepted: charging the seed frame legitimately produces one fewer frame
  in a short benchmark window at low caps. D2 hit, accepted: a stalled client gets an abrupt reset
  rather than a Close frame, and abort means the `client_count` decrement can be skipped, which is
  moot on the shutdown path but must not be relied on elsewhere. D3 hit, accepted: a client that
  explicitly sends `null` now has that field ignored instead of failing the command, so client
  mistakes get quieter. Designed out for D2: nothing may clear `client_slot`, which is what regressed
  #1476 before; both proposers independently rejected touching it.
- **S2 under-reach.** D3: the instance is `code`/`text`; the class includes `key`, and the probe
  bounded the class to those three sites. D2: abort covers the class ("any indefinite await in a
  connection task") where awaiting would only cover the reported instance. D1: **designed out during
  scoring** — set `last_sent` only on a *successful* send. The current code is `let _ = ws_tx.send(...)`
  for the seed, so a failed seed send would otherwise stamp a second phantom timestamp, which is the
  same defect one variant deeper.
- **S3 direction inheritance.** D1 arrives already two-way because `ctate` reported both directions.
  No third direction found.
- **S4 proxy property.** D1: a test must assert the *gap between consecutive deliveries*, not an
  average rate, because a 3s average absorbs one mis-timed frame. D2: "shutdown returns quickly" is a
  proxy for "no reader can still act"; the real property needs an observable tied to the reader.
- **S5 unregistered peer.** D4 hit: the id now exists in two representations, the envelope field and
  the wire JSON, with nothing enforcing agreement. Designed out by assigning it once into a local and
  using that local for both.
- **S8 guard-derived cells.** D3: test cells are derived from what the *dashboard* emits, not from the
  fields the fix inspects. The dashboard is the composed client that omits fields.
- **S9 test pins the wrong thing.** The gate's most valuable output, and neither proposer could have
  produced it because neither ran the artifact. The D2 regression test both proposals imply, "input
  stops reaching the browser after shutdown", **passes today without the fix**. The correct observable
  is one the reader still touches when the CDP client is dead: `idle_activity`, which `reader_loop`
  marks inside the `client_slot` guard while the slot still holds a live `Arc<CdpClient>`. D1: the
  existing `test_max_fps_cap_skips_stale_frames` passes with the bug present, so it cannot be the guard.
- **S10 claim from prose.** Codex's `char` claim was load-bearing and was verified against the real
  artifact rather than accepted: documented, and broken.
- S6, S7 not applicable: no cross-process version contract, no diagnostic delivery path.

## 5. Synthesis

**Kind: graft, plus one element neither proposal contained.**

- D1, D3, D4: taken as the converged shape, with two scoring amendments — `last_sent` moves only on a
  successful send (S2), and the D1 guard asserts consecutive gaps rather than an average (S4).
- D2: `codex`'s ownership boundary (`JoinSet` in `accept_loop`, drained before `accept_loop` returns,
  so `shutdown()` needs no new field) grafted with `fable`'s abort-on-drop guard for the reader handle,
  which is what keeps the reader from outliving an aborted parent. Seam checked: aborting the parent
  connection task must also stop the reader, and the guard is the only thing that provides it, because
  `JoinSet::shutdown` aborts the tasks it owns and knows nothing about a handle spawned inside one.
- The element neither had: **the D2 test asserts on `idle_activity`, not on browser control**, per S9.

What the losing material had that was better: `fable`'s framing of D1 as "only send sites write the
clock" is the clearer invariant and is what goes in the comment; `codex`'s explicit note that
`cdp_loop.rs` needs no change for D2 correctly bounds the blast radius. Both are kept.

Not taken: `codex`'s "writer as a separately cancellable future" as the *primary* mechanism. Abort of
the connection task already cancels a parked send, so restructuring the writer into a droppable future
adds control flow without adding a guarantee. Recorded because if abort turns out not to cancel a
parked `ws_tx.send()` promptly, this is the fallback.

## 6. Handoff

Assumptions to verify during implementation: prompt cancellation of a parked `ws_tx.send()` under
abort; no consumer bound to the `Arc<String>` payload type; `idle_activity` is observable from a test
without a live browser.

Must-not-change list goes to Review Gate step 5 as a driven checklist, not a reasoned one.

Issue candidate surfaced by a probe, outside all four defects: the documented `char` keyboard shape
and the documented `keyUp` example (`key` + `code`, no `text`) are both non-functional today, so all
three keyboard examples in `docs/src/app/streaming/page.mdx` are broken, not just the one D3 names.
This is inside D3's fix but widens its regression matrix.
