## Divergence that mattered

On D1/D2 the two proposers split on where the daemon's declaration lives.

- **Fable: a separate marker file** (`proxy.hosts-sync`), following the repo's existing
  `proxy.tls` / `proxy.lan` idiom. It explicitly rejected folding capability into the status
  file, on the grounds that it mixes "what happened" with "what I am" in one schema.
- **gpt-5.6-sol: extend the status file** into a declaration plus latest outcome, carrying a
  protocol version, publisher PID, and mode.
- **Implemented shape: extend the status file**, with publisher PID and mode, no protocol
  version.

Fable's rejection reasoning assumed the declaration would be published through the warm-up sync
path, which the implemented shape does not do: it writes the handshake in the `listen` callback,
beside the PID, and the reader's hostname-coverage filter structurally prevents a handshake from
satisfying a waiter. So the stated objection does not land on the implemented shape.

The objection *behind* it does. It is the same weakness the sealed record listed first: the file
now carries two kinds of record distinguished only by `hostnames` being empty, so a future
reader that ignores `hostnames` misreads a handshake as a successful sync. Probed: no current
reader does. Recorded as a residual risk, not rebuilt. Two of three choosing "extend" is a vote,
and a vote is not evidence.

## Scoring against recorded failure shapes

Both proposals were scored against `skills/.experimental/solution-gate/references/failure-shapes.md`.

- **S5 (unregistered peer)**: the implemented shape shares a constant between writer and
  remover, which couples the two for *this* file and not for the next one. Both proposals scored
  the implemented approach as still exposed and proposed a coupling that fails loudly: Fable a
  registry plus a test asserting every exported filename constant appears in it, gpt a shared
  artifact definition owning name, temp pattern, and matcher, plus a cleanup test that calls the
  real writer. **Hit on the implemented shape. Taken.**
- **S9 (test pins the wrong thing)**: the D4 documentation was corrected with no test asserting
  the behavior the new wording describes, so the claim can drift again silently, which is
  exactly how it drifted three times. **Hit on the implemented shape. Taken.**
- **S6 (peer-version blindness)**: absence of the file answers "old build" today. It does not
  answer "newer build, changed schema". gpt's protocol version makes the unsupported case
  explicit instead of inferred. **Partial hit. Taken.**
- **S3 (direction inheritance)**: none of the three proposals inherited a single direction; the
  suppression direction was already in the brief.

## Synthesis

**Kind: graft.** The implemented D1/D2 shape stands, corroborated by an independent proposer
reaching it from a symptom-free brief. Three changes are grafted on:

1. gpt's **protocol version** field in the declaration, turning an unsupported peer from an
   inference into a statement.
2. The **writer-cleaner coupling test** both proposers proposed independently. gpt's form is
   narrower and cheaper than Fable's full registry: a cleanup test that drives the real writer,
   so changing either side alone goes red. Fable's registry is the better end state and is
   recorded as a follow-up rather than done here, because it is a cross-file refactor with no
   defect currently behind it.
3. Fable's **D4 integration test** pinning two terminal warnings against one daemon log line,
   with gpt's more precise three-clause wording for the surfaces.

**Not taken:** Fable's separate marker file. Reason recorded above, with the residual.

## Finding produced about already-shipped code

Both proposers, independently, named a property of the shipped fix that the implementer had not:
a new CLI against an older daemon that syncs and fails is now **fast and silent**, where before
it was slow and silent. Fable called it transitional but real; gpt called it choosing a fast
false negative over a guaranteed 4.1 second delay. Neither proposed removing it, and the
implementer accepts it: the old daemon has no reporting channel, so no shape can surface that
failure without the CLI inferring something about a process it cannot see, which is the property
D2 forbids. Recorded as an accepted cost that the sealed record failed to state.
