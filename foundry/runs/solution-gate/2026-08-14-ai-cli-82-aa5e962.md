## Proposal A

### Shape

Keep MDX as the only checked-in content authority. Add one pure MDX AST serializer that owns plain-Markdown semantics for the supported components. `Cards` become Markdown lists, `Properties` become structured option sections, `Steps` become ordered steps, and `Callout` becomes a labeled blockquote. Unknown components fail loudly.

Keep explicit `.md` routes. Avoid user-agent branching for primary identity, but preserve the candidate's negotiated agent path if product requirements demand it. Valid page metadata owns canonicals and Markdown alternates. Omit freshness when content history is unavailable.

### Predictions

1. `curl /docs/commands.md` contains no `<Property` and still contains `--timeout`, `seconds`, and `300`.
2. `curl /docs/index.md` contains card descriptions, three steps, code fences, and the callout text, with no component JSX.
3. An unknown component fixture makes the converter test fail.
4. A no-git build emits no freshness value.
5. HTML missing routes remain 404 with no identity links.
6. Social bots keep receiving HTML with OG tags.

### Cost

- One serializer module and direct AST dependencies.
- Tests for every supported component and ordinary Markdown preservation.
- A maintenance obligation whenever the HTML MDX component contract changes.
- Metadata ownership moves from root layout to individual valid pages.

### What it makes worse

The serializer is a second renderer of component semantics. New component attributes can drift unless tests compare the supported component contract with Markdown output.

### Rejected alternatives

- Raw MDX: violates plain-Markdown semantics.
- Checked-in `.md` copies: creates a second content authority.
- Filesystem mtime: deployment materialization is not content freshness.
- Global identity metadata: error routes inherit a real page's identity.

## Proposal B

### Shape

Keep MDX as the sole source and use an AST transformer for semantic Markdown. A dedicated route owns Markdown output. Page metadata owns canonical and alternate links. Freshness uses explicit frontmatter first, Git history second, and omission otherwise.

### Predictions

1. Markdown routes have `text/markdown` and no component JSX.
2. Missing Markdown routes return 404.
3. HTML pages advertise one Markdown alternate.
4. Rebuilds keep freshness stable.
5. Sitemap contains only canonical HTML URLs.
6. Social bot OG behavior matches the baseline.

### Cost

- New transformer and route code.
- Direct AST dependencies.
- Component mapping maintenance.
- Git history work at build time if freshness is retained.

### What it makes worse

Every new custom MDX component needs a plain-text representation. A forgotten mapping produces broken discovery output.

### Rejected alternatives

- Raw MDX because it leaks JSX.
- Filesystem mtime because it changes on deployment.
- Parallel generated files because they introduce drift.

## Synthesis

Kind: **Amend**.

Keep the candidate's route topology, discovery inventory, agent negotiation, social-bot behavior, canonical normalization, OG metadata, robots, sitemap structure, and generated Markdown not-found behavior.

Make three bounded changes:

1. **Semantic MDX serializer**
   - Add a pure AST transformation used by `markdownForPathname`.
   - Convert `Card/Cards`, `Property/Properties`, `Step/Steps`, and `Callout` into ordinary Markdown structures.
   - Preserve normal Markdown, GFM, code fences, languages, links, and tables.
   - Fail loudly on unsupported MDX components.
   - Declare AST packages as direct `apps/web` dependencies.

2. **Freshness omission**
   - Remove filesystem `mtime`, the fixed fallback date, sitemap `lastModified`, and Markdown `last_updated`.
   - Do not add Git subprocess coupling in this fix. If freshness becomes a product requirement, add explicit frontmatter or a build-generated manifest in a separate change.

3. **Route-owned identity metadata**
   - Keep `metadataBase` and non-identity site defaults in the root layout.
   - Move homepage canonical and Markdown alternate to `apps/web/app/page.tsx`.
   - Keep docs identity in `generateMetadata`.
   - HTML 404s then inherit no canonical or Markdown alternate.

The genuinely better part of Proposal B is Git-derived freshness when available. It is not selected because freshness is optional and omission removes lifecycle inconsistency, subprocess cost, and another failure surface.
