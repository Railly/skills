## Proposal A: Fable 5

### PR #366

#### Shape

A parser-layer change confined to the argv rewriter, in three parts. First, Vite's bare positional (`vite ./app`) is classified as the root of a default dev server, so injection proceeds instead of bailing on an unknown subcommand. Second, runner separators such as `--` in `npm run dev -- ...` are owned by the runner's grammar: generated `--port` and `--host` are inserted into the segment of argv owned by the framework, never into the runner's own arguments. Third, Expo's `--localhost`, `--lan`, and `--tunnel` are modeled as aliases of `--host`: if the user passed any of them, the generated `--host` is suppressed, but `--port` is still injected. All non-server exclusions, value-flag parsing, direct, runner and script paths, port and host injection independence, unsafe-script declines, and Expo's LAN behavior are untouched.

#### Predictions

1. `portless run vite ./app`: the spawned process argv, verified with `ps -o args` or an argv-echo stub, contains injected `--port <p>`, and `curl -sf http://127.0.0.1:$PORT/` serves the app from `./app`.
2. With a script `dev: vite`, `portless run npm run dev -- --open` yields child argv where `--open --port N --host H` all appear in the Vite segment. `npm` itself receives no injected flags. Verify by replacing `vite` with an argv-echo stub.
3. `portless run npx expo start --tunnel`: child argv contains injected `--port` and contains no generated `--host`. The same holds for `--localhost` and `--lan`.
4. `portless run vite build ./app` receives zero injected flags, and `portless run vite --port 4000` receives an injected `--host` but no second `--port`.

#### Cost

More framework grammar is hardcoded: an Expo alias table, the Vite positional-is-root rule, and separator-aware insertion points. Each is a table that must track upstream CLIs, and the tokenizer gains branches that every command classification pays for in review complexity. Runtime cost is negligible.

#### What it makes worse

The failure mode shifts from visible to quiet. Before, an unrecognized shape meant no injection. Now a typoed subcommand such as `vite biuld` is classified as a root directory and gets server flags injected into a command that will fail with confusing extra arguments. When Expo adds a host-mode flag, Portless can inject a conflicting `--host` instead of abstaining. Misparse errors become wrong placement rather than absence.

#### Rejected alternatives

- Append generated flags at the end of argv unconditionally. Runner and subcommand grammars can consume them in the wrong region.
- Treat every unknown positional as unsafe and decline. That rejects the required `vite ./dir` form.
- Suppress both `--host` and `--port` when an Expo mode flag is present. That violates port and host independence.
- Inject through a spawn shim after runner resolution. That expands the blast radius and abandons the unsafe-script decline model.

### PR #374

#### Shape

Two areas. First, when startup finds an existing daemon that does not speak the current protocol, it fires the mute trigger and waits a short bounded window, sized so existing five-second integration tests remain below timeout while an old daemon still has a chance to act. Second, the `.local` exemption applies only when LAN mDNS mode is active, the internal host match accepts only exact loopback IP authorities (`127.0.0.1`, `::1`) rather than name prefixes, and hosts-file matching compares every hostname token on every valid line. The current, old and absent daemon distinctions, loopback-peer security, same-path app routing, and no-persistent-artifact invariant are preserved.

#### Predictions

1. Timing the daemon-takeover integration test before and after shows the delta below the bounded wait, and every previously passing test finishes below five seconds.
2. With a wedged old daemon that ignores the protocol, startup lasts approximately the bound and then proceeds or errors deterministically, never indefinitely.
3. With mDNS mode off, an unresolved custom `.local` route is checked and warned. With LAN mDNS mode on, the same suffix is exempt from loopback resolution.
4. A request with authority `127.attacker.example` is not treated as internal, while `127.0.0.1` remains internal.
5. With `127.0.0.1 first.test myapp.test`, both aliases are parsed as mappings, a substring does not match, and no persistent state artifact is created.

#### Cost

Every startup that encounters a stale daemon pays the fixed bounded wait. Tightened `.local` and loopback rules change behavior for users relying on spelling rather than configured mode. Hosts parsing does more work per line.

#### What it makes worse

An old daemon that legitimately needs longer than the shortened window can lose the race. The new daemon may fail to bind or leave the old process holding the socket. This trades CI timeout safety for timing-dependent startup errors on slow machines.

#### Rejected alternatives

- Raise integration-test timeouts. This masks regressions and slows CI.
- Poll the port with no bound. A wedged daemon can hang indefinitely.
- Keep a spelling-based `.local` exemption behind an allowlist. It still decides from spelling.
- Resolve the request Host through DNS. It resolves attacker-controlled names during request handling.
- Add a pidfile or lockfile. It violates the no-persistent-artifact invariant.

## Proposal B: OpenAI GPT-5.5

### PR #366

#### Shape

Introduce a framework invocation parser that returns the framework name, framework argument slice, server versus non-server classification, and insertion index. Make suppression checks only inside the framework-owned slice, with `--port`, `--port=...`, `--host`, `--host=...`, and Expo connection-mode flags treated as equivalent user choices. Classify Vite grammar explicitly: no subcommand with a positional root is server, `dev` is server, `build` and `optimize` are not. Treat runner separators such as `npx -- vite dev` as runner grammar, then insert generated flags after Vite-owned args, not before the framework command.

#### Predictions

- `pnpm --filter portless test -- src/cli-utils.test.ts -t "injectFrameworkFlags"` shows `["vite", "./app"]` becoming `["vite", "./app", "--port", "4567", "--strictPort", "--host", "127.0.0.1"]`.
- `pnpm --filter portless test -- src/cli-utils.test.ts -t "npx separator"` shows `["npx", "--", "vite", "dev"]` retaining `--` before `vite` and appending generated flags after `dev`.
- `pnpm --filter portless test -- src/cli-utils.test.ts -t "expo connection mode"` shows `expo start --localhost`, `expo start --lan`, and `expo start --tunnel` receiving `--port 4567` but no generated `--host`.
- `pnpm --filter portless-e2e test:e2e -- src/vite.test.ts` shows a bare `vite ./app` fixture listening on the assigned Portless port rather than Vite's default.

#### Cost

The parser needs a small per-framework grammar table, including known option arity, because first positional token is insufficient once options can take values before subcommands.

#### What it makes worse

Grammar tables create maintenance drag. A future framework release can add a server subcommand or an option with a value, and Portless may need an update before injection is correct again.

#### Rejected alternatives

- Always append flags to the full command. `npx -- vite dev` requires placement inside the framework-owned region.
- Treat every Vite positional token as a subcommand. `vite ./app` is a project root and a valid server invocation.
- Suppress Expo host injection only for `--host`. Expo's connection-mode flags are equivalent user choices and conflict with generated `--host`.

### PR #374

#### Shape

Add a loopback-only internal POST trigger for `/.portless/hosts-sync` that is selected only when the peer is loopback and the request authority is a loopback authority, not merely a hostname starting with `127.`. Registration posts to that endpoint with a short request timeout. If acknowledged, report resolution immediately. If a real Portless producer exists but does not acknowledge, give the route watcher a bounded fallback window. If no producer exists or connection is refused, warn without paying that fallback ceiling.

Move reporting decisions through a helper that uses effective configured TLDs, LAN mode, mDNS availability, and protocol semantics. `.local` is skipped only for active LAN mDNS routes. A custom `.local` TLD outside active mDNS is still checked for loopback resolution. Replace hostname-only managed-block checks with exact mapping comparison: desired hostnames must appear once, on `127.0.0.1`, with no extras, duplicates, or wrong-address entries inside the managed block.

#### Predictions

- `pnpm --filter portless test -- src/proxy.test.ts -t "hosts-sync"` shows `POST /.portless/hosts-sync` with Host `127.evil.test` proxied to the registered app, while Host `127.0.0.1` invokes the internal trigger.
- `pnpm --filter portless test -- src/hosts.test.ts -t "managed block exact"` shows `127.0.0.1 active.test stale.test` not matching desired `["active.test"]`.
- `pnpm --filter portless test -- src/cli.test.ts -t "custom local resolution"` shows a non-LAN `.local` route attempting resolution reporting and warning when unresolved.
- `time pnpm --filter portless test -- src/cli.test.ts` keeps mock-proxy registration tests below their five-second timeout when the mock does not acknowledge `/.portless/hosts-sync`.

#### Cost

This adds another internal proxy control path and a timing-sensitive registration probe, so tests need fake timers or an explicit process boundary to avoid flaky duration checks.

#### What it makes worse

A very slow older daemon may get less time to sync hosts through its file watcher than before. The behavior is bounded by design, but it can surface a warning that a longer wait would have avoided.

#### Rejected alternatives

- Route the internal endpoint when the Host string starts with `127.`. `127.evil.test` is a legitimate app hostname.
- Skip all `.local` resolution warnings. Custom `.local` configurations without mDNS still require resolution reporting.
- Compare only the second column of managed lines. Extra aliases on the same line remain unmanaged by that comparison.
